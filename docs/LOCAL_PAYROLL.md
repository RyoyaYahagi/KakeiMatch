# 給与明細から収入を登録する

「＋追加 → 収入 → AIで簡単入力」を押すと直接カメラが起動します。撮影後は個人情報のマスキングへ進みます。撮影をキャンセルした場合は、元の収入入力と入力内容を保持します。給与明細画面では撮り直しや写真の選び直しもできます。通常の収入手入力も引き続き使えます。

## 写真と読み取り

写真は端末のメモリだけで開きます。送信前に、氏名、社員番号、マイナンバー、住所、生年月日、銀行口座・支店番号、QRコード・バーコードを隠してください。隠す範囲の左上と右下を順にタップすると黒く塗りつぶします。複数箇所に使えます。マスキングは利用者が行い、自動で個人情報を検出する機能はありません。

個人情報を隠したこととAI送信を確認した場合だけ、メタデータを含まない画像に描き直して送ります。勤務先、支給日、額面、手取り、控除と支給項目を構造化します。読めない値は空欄です。撮影日や対象月から支給日を補完せず、総支給額と控除から手取りを計算し直しません。給与と賞与は別の種類です。

画像内の命令は採用しません。応答は許可された項目だけをschemaで検証します。警告は固定の分類だけを受け取り、OCR全文、自由文警告、社員情報などの追加フィールドは拒否します。名前や項目名に識別番号らしい長い数字列・識別情報のラベルがある場合も拒否します。これは個人情報の完全な自動検出を保証するものではないため、送信前のマスキングが必要です。

読み取り成功・失敗・キャンセル・画面移動で画像とファイル選択を破棄します。画像はIndexedDB、Actual、バックアップ、同期へ保存しません。失敗後は写真を選び直すか、手入力できます。AI要求は既存の認証、同一origin検証、利用枠、レート制限、費用上限を使い、providerへ`store: false`を指定します。ログに給与内容を追加しません。

## 確認と登録

勤務先、支給日、手取り、収入カテゴリ、銀行口座を確認します。「支給・控除の内訳」を開くと、対象期間、給与・賞与の種類、額面、主要控除、支給項目を修正できます。読み取り値の確認チェックが必要です。「給与」カテゴリと銀行口座がなければ画面内で追加できます。口座番号から口座を自動作成しません。

Actualには手取りの収入1件だけを登録します。控除の支出は作りません。同月・同勤務先の収入、定期収入、登録途中の給与があれば警告します。既存の記録を開いて確認し、必要な場合だけ「それでも登録」を選べます。定期給与を実額へ自動更新する処理はMVPに含めません。給与・賞与が同月の場合も安全側に警告します。

確認後の登録開始時に、構造化した付帯情報を`payroll-record`として端末に保存します。Actual登録と保存完了の間で失敗した場合は、確認済みの値と同じ登録IDで再試行します。収入画面から給与明細入力へ戻ると、登録途中の給与を再開します。写真は再試行用にも保持しません。

## 記録・編集・削除・バックアップ

登録した収入の詳細から、登録時に確認した給与内訳を開けます。付帯情報はActualのtransaction IDへ結び付きます。通常の取引編集後も参照を保持し、内訳は「登録時」の履歴として扱います。取引を削除しても取り消し・履歴のため付帯情報を保持します。削除された取引を内訳だけから再作成することはありません。

`.kmb`の書き出し・復元と端末間の家計簿同期には、schema検証済みの構造化情報だけを含めます。画像、Base64、OCR全文、モデルの生応答、個人識別番号は含めません。

## 検証

完全な合成値によるschema・登録・再試行・重複警告・バックアップ復元の単体テストと、375px幅のブラウザーE2Eを用意しています。E2E画像もコードで生成した合成画像です。実給与明細は使いません。実際のAIによる読み取り精度とiPhoneホーム画面PWAでの操作は、実機確認が別途必要です。
