# Museへの読み取り専用スナップショット

KakeiMatch iOS（`apps/ios`）の家計データのうち、残高・取引・月次のカテゴリ別支出だけをJSONファイルに書き出し、利用者のAIアシスタント（Muse）が読み取り専用で使えるようにする。月次の家計レビューなど、後段の自動化の土台にする。データ形式は[スナップショット形式 v1](MUSE_SNAPSHOT_SCHEMA_V1.md)に定める。

この文書は設計判断の記録です。2026-11-08に利用者の確認を得ています。

## 前提と制約

- 家計データの正本は利用者のiPhoneにあるネイティブiOSアプリの端末内SQLiteです。PWAは今回の対象外です。
- 開発者が運用する常駐サーバーを置かない。利用者の家計データを開発者のサーバー（Cloudflare Worker、D1、R2を含む）へ通さず、保存もしない。
- 読み取り専用。Muse側からKakeiMatchのデータを変更する経路を作らない。
- 既存のアプリの動作、バックアップ、復元を変えない。機能は既定で無効にし、利用者が設定画面から書き出したときだけ動く。

## 決定

アプリが本人のGoogle Driveへスナップショットを書き出し、Muse側のCLI（`tools/kakeimatch-read`）がそれを読む。らくストック（Stockpile）のMuse連携と同じ「利用者側で完結する」方式です。

```text
iPhone（KakeiMatch iOS）
  │ 書き出しのみ。アプリはDriveから読み込まない
  ▼
本人のGoogle Drive: KakeiMatch/snapshot.json
  │ 読むだけ（Drive連携、rclone cat、手動ダウンロードのどれでもよい）
  ▼
Muse: kakeimatch-read balances | transactions | monthly
```

段階を2つに分けます。

1. **共有シートでの書き出し（先に入れる）**: 設定画面で期間を選んでスナップショットを作り、iOSの共有シートから「ファイル」アプリ経由でDriveの `KakeiMatch` フォルダへ保存する。GoogleのOAuthクライアント登録を待たずに、実データでの読み取りを確かめられる。Drive連携が使えないときの予備にもなる。
2. **Driveへの直接書き込み（実装済み、実機確認待ち）**: Google Sign-Inで `drive.file` 権限だけを求め、アプリが作った `KakeiMatch/snapshot.json` を上書きする。GCPのOAuthクライアント登録と同意画面の記載を利用者が済ませてから実装した。

### 含めるもの

利用者の指定（2026-11-08）により、最初は残高・取引・月次のカテゴリ別支出だけに絞ります。

- 口座ごとの現在残高
- 書き出し時に指定した期間（月単位）の取引。店名（`payeeName`）とメモ（`memo`）を含む
- 同じ期間の月ごとの収入・支出・カテゴリ別支出

月ごとの集計値は、アプリのホーム画面と同じ `TransactionRepository.home(month:)` の結果を書きます。Muse側で取引から計算し直した値と画面の値がずれないようにするためです。CLIは取引から計算し直した値と比べ、ずれていれば警告します。

レシート画像、明細CSV、照合の作業データ、予算、定期登録、給与明細の内訳、ログイン情報、AIの利用状況は含めません。必要になったら形式の版を上げずに追加できる項目か、別の形式にするかを都度判断します。

### Driveへの自動書き込み

設定のトグルは既定でOFFにし、OFFの間は自動・手動ともDriveへ書き込まない（「今すぐ保存」も押せない）。保存済みのGoogle Sign-Inの復元は、ONのときと、利用者が設定ページを開いたときだけ行う。ONにしたときだけ次のタイミングで書き込む（案C）。

- アプリの起動時と、前面に戻ったとき（`scenePhase == .active`）
- 設定ページの「今すぐ保存」

自動・手動とも、期間は書き出し時点の `KMMuseExportPresentation.defaultRange(today:)`（当月と過去2か月）で、`KMMuseSnapshotBuilder.build(...)` の出力をそのまま送る。保存先はDriveの `KakeiMatch` フォルダ直下の `snapshot.json` 固定で、既存ファイルがあれば中身を差し替える。

Driveに対して行う操作は次の3種類だけにする。中身の取得（`alt=media`）、削除、ゴミ箱への移動、権限の変更は行わない。アプリはDriveから読み込まない。

| 操作 | リクエスト |
| --- | --- |
| フォルダの作成 | `KakeiMatch` がなければ `POST /drive/v3/files` |
| ファイルの作成 | `snapshot.json` がなければ `POST /upload/drive/v3/files?uploadType=multipart` |
| ファイルの上書き | あれば `PATCH /upload/drive/v3/files/<id>?uploadType=media` |

401のときだけトークンを強制的に更新して1回やり直す。それでも401なら失敗として扱い、5xxなどは再試行しない。送信に失敗したときは最後に送った内容のfingerprintを更新せず、次に前面へ戻ったときにもう一度判定する（連続した再試行はしない）。Driveが返す英語のエラー文は画面に出さず、日本語の理由に置き換える。

接続するGoogleアカウントが変わった場合は、前のアカウントの保存履歴（最後に送った内容と日時）を引き継がず、新しいアカウントへ初回の自動保存を行う。

送信中に自動保存をOFFにした場合やサインアウトした場合は、その送信を中止し、成功日時やfingerprintを保存しない。起動時のサインイン復元が一時的な通信障害で失敗した場合は、次の前面復帰で再試行する。

### 暗号化しない

ファイルは平文のJSONです。保存先が本人のDriveだけで、らくストックと同じ扱いにすると利用者が判断しました（2026-11-08）。ファイルを他人と共有しないこと、共有フォルダに置かないことをアプリの画面で伝えます。

## 却下した案

| 案 | 却下した理由 |
| --- | --- |
| KakeiMatchのWorkerや暗号化同期の保存先（R2）に読み取りAPIを足す | 家計データが開発者の基盤を通るため、制約に反する |
| 利用者自身のCloudflare Workerへ送る（らくストックの旧方式） | 利用者にサーバーの構築、トークン管理、運用を負わせる。らくストックもこの方式をやめてDrive方式に移った |
| 既存のバックアップ（`.kmb` / `.kmib`）をCLIが直接読む | レシート画像を含む家計簿全体を渡すことになり、必要な範囲を大きく超える。CLIがActualのSQLiteとiOS専用形式の中身に依存し、アプリの内部構造の変更で壊れる |
| iCloud Drive / CloudKit | Linux上のMuseから安定して読む手段がない。保存先はGoogle Driveにすると利用者が決めた |
| 同じネットワーク内で端末から直接送る（WebRTCなど） | iPhoneでアプリを開いておく必要があり、定期的な自動化に向かない |
| 期間を13か月に固定する | 利用者の指定により、書き出し時に期間を選べるようにした |

## 読み取り専用の担保

- **データの流れが一方向**: アプリはスナップショットを書き出すだけで、Driveから読み込まない。既存の復元はスナップショットを受け付けない（テストで確認する）。
- **CLIに書き込み口がない**: CLIはファイルと標準入力から読むだけで、サブコマンドに書き込みがなく、子プロセスも起動しない。Driveからの取得（Drive連携や `rclone cat`）は呼び出す側が行う。rcloneの設定によっては読むだけで書き込みが起きる（`cache` など）ため、CLIの中からは呼ばない。ファイル・ネットワークへの書き込みや子プロセスを使わないことをテストで確認する。
- **Driveの権限を絞る**: 直接書き込みでは `drive.file` だけを求め、アプリが作ったファイル以外は見えない。
- **形式の取り違えを防ぐ**: スナップショットは `kind: "kakeimatch-snapshot"` を持ち、CLIは `.kmb` / `.kmib` や未対応の版を推測で読み替えずにエラーにする。

## 検証と証跡

- 合成データでの形式検証、集計の照合、書き込み経路がないことの確認は自動テストで行う。
- 実データでの読み取りは利用者のiPhoneで書き出したファイルを使う。実行ログには家計情報が含まれるため、リポジトリに入れない。リポジトリとPRには、コマンド、終了コード、`generatedAt`、件数だけを残す。
- 実機での確認項目は各PRの本文に載せる。
