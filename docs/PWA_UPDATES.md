# アプリ更新と端末内データ

アプリの配信資材は、buildごとのService Workerとキャッシュにまとめます。Workerは新しい版の画面と必要なJavaScript・CSSをすべて取得できた場合だけインストールを完了します。途中で通信が切れた場合、取得途中のキャッシュだけを捨て、動作中の版を残します。

## 利用者の更新手順

新しい版が待機している場合は、画面上部に案内します。

1. 入力中の作業を終える。手入力・レシートの下書きは従来の端末保存を使う
2. 他のタブを含め、開いているKakeiMatchの画面をすべて閉じる
3. アプリを開き直す

新しい版を強制的に有効化する `skipWaiting()` と、自動の再読み込みは使いません。旧版が制御している画面が残っている間は、旧版のキャッシュと画面を維持します。1つのタブを再読み込みしても、そのタブだけ新しいHTMLを取得しません。オフラインでも同じ版の資材で起動します。

すべての旧画面が閉じられた後、ブラウザーが待機中の新しいWorkerを自然に有効化し、旧版キャッシュを削除します。削除するのは `kakeimatch-shell-*` のアプリ配信用キャッシュだけです。IndexedDB、Actual Budget、レシート、明細、下書き、照合記録は削除しません。

## 資材の整合性

Service Workerの版には、buildの資材名とWorker sourceから生成した識別子を使います。資材名にはbundlerの内容hashが含まれるため、アプリ変更時にはWorkerも更新対象になります。手作業でキャッシュの番号を毎回上げる必要はありません。

各Workerは版別の `offline-assets-<build>.json` を取得します。manifestの版・資材のパスを検証し、HTMLが参照するbundleがmanifestに存在することを確認します。deploy途中でHTMLとmanifestが別の版になった場合は、インストールを失敗させます。旧Worker向けの `offline-assets.json` も互換用に残します。

navigationと資材の検索は、そのWorkerのキャッシュだけを使います。複数世代を横断する `caches.match()` は使いません。キャッシュにない `/assets/*` を新版のサーバーから補充せず、503で停止します。`/api/*` は引き続きキャッシュも横取りもしません。保存したHTMLのCOOP/COEP等のヘッダーはオフラインでも保持します。

## 構造の移行との関係

| 対象 | 方針 |
| --- | --- |
| HTML / JavaScript / CSS / Actual browser bundle | 同じbuildの資材として配信し、旧画面が残る間は切り替えない |
| KakeiMatch IndexedDB | 既存のバージョン判定と同じ更新トランザクション内の移行を再利用する |
| 未対応の新しいIndexedDB | 読み書きを停止し、更新と再起動を案内する |
| 別タブでのIndexedDB更新 | `versionchange`で旧接続を閉じ、古い接続から再保存しない |
| `.kmb`形式 | DB版と独立して検証する。未対応の形式を無理に書き出し直さない |
| Actual保存データ | 依存更新前に下記の互換検証を行う。アプリ資材キャッシュの消去で削除しない |

既存の移行失敗時の案内は [端末内データの構造変更](LOCAL_DATA_MIGRATIONS.md) を参照してください。破壊的な変換が必要になる場合の事前バックアップ案内・読み取り専用復旧画面は、本PRで実装済みとは扱いません。現在のIndexedDB version 2を変更するPRでもありません。

## Actual依存更新時の確認

本番のoriginは変えず、専用の合成profileで確認します。更新前の版で作成した家計簿と`.kmb`を使い、更新後の版で既存家計簿を開く、取引・カテゴリ・口座・残高を読む、バックアップへ書き出す、新しい保存先へ復元する、元の保存先へ戻る処理を確認します。空の家計簿だけの試験を互換確認とみなしません。

- rootの `local-data` / `actual-browser-ledger` / `local-backup` / `local-backup-format` のunit tests
- PWAの `test:e2e` と `test:backup-e2e` を実Actualブラウザー版で実行
- 旧版で作成したarchiveの新しい版への復元と、オンライン・オフライン再起動
- iPhoneホーム画面PWAで旧版からの更新を別途確認

依存変更時には、旧・新のActual版、合成データを作成したcommit、確認したcommit、結果をPRへ記録します。unit testが通るだけで既存家計簿との互換性を保証しません。

## 検証と残件

`test:updates-e2e`は2世代を配信する合成HTTPサーバーと実ChromiumのService Workerを使います。二つの旧タブ、新版ダウンロード失敗と再試行、待機の案内、入力保持、オンライン・オフラインの再読み込み、全タブを閉じた後の自然な有効化、旧キャッシュ整理、端末profileと下書きの継続を確認します。実際の家計情報は使いません。

今回の変更以前のv36 Workerは、navigationをオンラインのサーバーから取得する旧方式です。このコードは既に開いている旧Workerを遠隔で書き換えません。初回導入時は入力を終え、すべての画面を閉じ、オンラインで開き直して新版への移行を確認してください。旧方式からのiPhone実機確認を、今回の2世代合成テストで代用しません。

Issue #53は、初回導入とiPhoneホーム画面PWAの更新実機確認、破壊的移行前のバックアップ・復旧導線、Actual依存更新時の実データ構造との互換検証が残るため、openを維持します。
