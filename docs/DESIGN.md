# Design

この文書は、本番アプリ `apps/pwa` の見た目の基準です。画面構成と操作は[UX](UX.md)に定めます。

見た目の全体像は、モック [design-mockup.html](assets/design-mockup.html) で確認できます。ブラウザーで開くと、画面の例とライト・ダークの表示を見られます。モックと食い違う場合は、この文書を正とします。

## デザインの目標

KakeiMatchは、家族が毎日開いても疲れない、**明るく親しみやすい生活の道具**を目指します。見た目の考え方は「台帳と印鑑」です。紙の帳簿に罫線で記録を書き、照合が済んだものに印を押す、という見立てで画面を組みます。

- あんず色の温かい紙の上に、罫線で区切った行を並べる。カードや面を量産しない
- 照合が済んだものには「済」の印を1つ押し、件数だけ見せる
- 金額は伝票のように等幅の数字で揃え、桁で見比べられるようにする
- 記録なしは「危ない」ではなく「まだ見つからない」。失敗と同じ色にしない
- 派手な演出より、読みやすさ、予測しやすさ、操作の少なさを優先する

## 実装の方針

- UIは現行どおり、フレームワークを使わずTypeScriptでDOMを組み立てる。UIフレームワークへの移行はしない
- 色、余白、角丸、文字サイズはすべて `apps/pwa/src/style.css` の `:root` にCSS変数（デザイントークン）として定義する。各画面やTypeScriptに色コードや任意の値を直接書かない
- 繰り返し使う部品（下部ナビ、台帳の行、帳簿の行の入力、状態の表示、ボタン）はクラスと小さなDOMヘルパーにまとめる。同じ役割の部品を画面ごとに作らない
- inline styleは使わない。進み具合の割合など、データで決まる値だけをCSS変数で渡す

## デザイントークン

### 色

意味ごとに名前を付けます。ライトとダークで値を切り替え、名前は共通にします。

| トークン | ライト | ダーク | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#FAF6F1` | `#17120E` | 画面の背景。台帳の行はこの上に直接並べる |
| `--surface` | `#FFFFFF` | `#221B15` | 面を作る時だけ使う（下記）、ナビ、シート |
| `--sunken` | `#F3EBE1` | `#2B221B` | 切り替えの下地、バーの下地、読み取り中の仮の帯 |
| `--text` | `#2E2219` | `#F2E9E0` | 本文 |
| `--muted` | `#6E5F52` | `#B3A493` | 補足、項目名、未選択のナビ |
| `--border` | `#ECE2D7` | `#382D24` | 罫線、面の枠 |
| `--border-strong` | `#C9B6A2` | `#5E4D3F` | 未選択の丸いボタンの枠、ミシン目 |
| `--primary` | `#A94C16` | `#FFA56B` | 主要ボタン、＋追加、リンク、選択中、入力中の下線 |
| `--on-primary` | `#FFFFFF` | `#2A1205` | 主要ボタンの文字 |
| `--primary-soft` | `#FCE9DC` | `#3D2414` | 選択中の背景 |
| `--success` / `--success-soft` | `#B3361F` / `#FBE7E1` | `#FF8C72` / `#3B1D17` | 照合済み（朱の「済」の印）、完了 |
| `--warning` / `--warning-soft` | `#3F55B5` / `#E6EAFB` | `#AEB6FF` / `#262C55` | 要確認、注意 |
| `--missing` / `--missing-soft` | `#8A3A78` / `#F6E5F0` | `#F0A6DA` / `#3A1E33` | 記録なし |
| `--danger` / `--danger-soft` | `#9E1B32` / `#FBE3E7` | `#FF8FA3` / `#3D1820` | 反映の失敗、削除 |
| `--income` | `#2D6FA8` | `#8DC0F0` | 収入の金額 |
| `--scrim` | `rgb(46 34 25 / .45)` | `rgb(0 0 0 / .6)` | シートやダイアログの背後 |

状態と色の対応は固定します。状態は必ず記号と文言も添えます（[UX](UX.md#状態を色だけで伝えない)）。

| 状態 | 色 | 記号 |
| --- | --- | --- |
| 照合済み・完了 | success（朱） | ✓、「済」の印 |
| 要確認 | warning（藍） | △ |
| 記録なし | missing（紫） | ! |
| 反映の失敗 | danger（深紅） | ! |

色の選び方の理由と注意を残します。

- 主要色を橙にしたので、要確認を一般的な黄色にすると主要色と見分けられない。要確認は藍にする
- 照合済みの朱は、主要色の橙と明るさが近い。朱は「済」の丸い印・✓・文言とセットでだけ使い、ボタン・選択中・リンクには使わない
- 失敗の深紅と照合済みの朱も近い系統なので、失敗は必ず「!」と「反映できませんでした」等の文言を付けた帯で示す
- 記録なしは、不正を連想させないよう赤系を避けて紫にする

`*-soft` の背景には、同じ役割の濃い色の文字を載せます。どの組み合わせも4.5:1以上のコントラストを保ってください。トークンを追加・変更する時は、ライトとダークの両方でコントラストを確かめます。

### カテゴリの色

カテゴリのアイコンは、淡い円（`-soft`）に濃い色（前景）の線で描きます。色はカテゴリを区別する補助です。名前は必ず文字で書きます。アイコンの線と背景のコントラストは3:1以上にします。カテゴリの色を文字の色に使わないでください。

| トークン | ライト 前景 / 背景 | ダーク 前景 / 背景 | 初期の割り当て |
| --- | --- | --- | --- |
| `--c-food` | `#D9661F` / `#FFE8D6` | `#FFA766` / `#3B2616` | 食費 |
| `--c-daily` | `#0B7A68` / `#E4F5EF` | `#45C7A8` / `#173A32` | 日用品 |
| `--c-transport` | `#2D66B5` / `#E0EBFA` | `#8DB8F5` / `#182A44` | 交通 |
| `--c-fun` | `#B23C74` / `#FBE2EE` | `#F28DBC` / `#3A1A2B` | 娯楽、衣服 |
| `--c-util` | `#946600` / `#FFF1C7` | `#F0C150` / `#3A2E0E` | 水道・光熱 |
| `--c-comm` | `#6450BF` / `#ECE8FB` | `#B3A5F5` / `#241F45` | 通信、医療 |
| `--c-other` | `#5E6A65` / `#E8ECEA` | `#A9B4AF` / `#262E2B` | その他、振替 |

利用者が追加したカテゴリには、この7色を順に割り当てます。支出の内訳の帯グラフの「その他」は `--c-other` を薄く表示します。

### 文字

フォントは端末の標準フォントを使います。Webフォントは読み込みません。オフラインで使え、外部へ通信しないためです。

```css
--font-body: -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", "Yu Gothic UI", system-ui, sans-serif;
--font-num: ui-monospace, "SF Mono", Menlo, "Roboto Mono", monospace;
```

金額・件数・日付の数字は `--font-num` に `font-variant-numeric: tabular-nums` を付けて、伝票のように桁を揃えます。店名や品名など文字の部分は `--font-body` のままにします。

| 役割 | サイズ / 太さ | 使う場所 |
| --- | --- | --- |
| 大きな金額 | 40〜44 px / 700 | ホームの今月使ったお金 |
| 入力中の金額 | 30 px / 700 | 帳簿の行の入力の金額 |
| 画面の見出し | 22 px / 900 | タブの画面名 |
| 小見出し・上部バー | 15〜17 px / 700〜900 | まとまりの見出し、作業画面の上部 |
| 本文・行の主な文字 | 15〜16 px / 400〜500 | 店名、入力値、ボタン |
| 補足・項目名 | 12〜13 px / 400〜700 | 行の補足、帳簿の行の項目名、日付の見出し |
| ナビのラベル | 11〜12 px / 400（選択中は700） | 下部ナビだけ |

- 金額の記号は、支出に「−」（U+2212）、収入に「+」を使う
- 見出しの段階は3つまでにする。太さだけで多くの段階を作らない
- 行の高さは本文で1.5〜1.6を基準にする
- まとまりの見出しは12 pxで、少し字間を空ける（`letter-spacing: .1em`）

### 余白

4 pxの倍数の段階だけを使います。

| トークン | 値 | 主な用途 |
| --- | --- | --- |
| `--space-1` | 4 px | アイコンと文字の間 |
| `--space-2` | 8 px | ボタン同士、行内の要素の間 |
| `--space-3` | 12 px | 行のアイコンと文字の間 |
| `--space-4` | 16 px | 画面の左右の余白、まとまり同士 |
| `--space-5` | 20 px | 大きなまとまりの間 |
| `--space-6` | 24 px | 画面内の大きな区切り |
| `--space-8` | 32 px | 画面下部の余白 |

画面の左右の余白は16 pxです。iPhoneの切り欠きとホームバーには `env(safe-area-inset-*)` を足します。

### 角丸と影

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--radius-sm` | 10 px | 行のアイコンの背景、切り替えの中のボタン |
| `--radius-md` | 12 px | 補助ボタン、切り替えの下地 |
| `--radius-lg` | 16 px | 主要ボタン、件数の枠、伝票、「レシートを撮る」 |
| `--radius-xl` | 18 px | 確認することの箱、＋追加（角丸の四角） |
| `--radius-sheet` | 24 px | 下から出るシートの上の角 |
| `--radius-full` | 999 px | 丸いボタン、バッジ、「済」の印 |

影はライトだけでごく弱く付けます（`--shadow: 0 1px 3px rgb(46 34 25 / .06)`）。ダークでは影を付けず、面の明るさの差で区別します。中央の「＋追加」ボタンにだけ、浮いて見える影を付けます。

## 部品

`components/` のようなディレクトリは作りません。部品はCSSのクラスと、`apps/pwa/src` の小さなDOMヘルパーで表します。部品には家計の知識を持たせません。家計の意味を持つ組み立て（記録の行、照合の行など）は各画面のモジュールに置きます。

### アプリの枠と下部ナビ

- 本文の最大幅は640 px。画面の上部にアプリ名や説明文を常に出さない（PCの表示は[レスポンシブ](#レスポンシブ)）
- 下部ナビは `--surface` の面に上の罫線を引く。高さはホームバーの余白を含めて84 pxを目安にする
- 各タブはアイコン（22〜24 px）とラベルを縦に並べる。選択中は `--primary` の色・太字に加え、タブの上端に幅24 px・高さ3 pxの線を引く
- 中央の「＋追加」は56 pxの角丸の四角（`--radius-xl`）で、`--primary` で塗る。ナビの上へはみ出させ、下のラベル（「追加」）の高さは他のタブと揃える
- 照合のバッジは、`--warning` の背景に `--surface` 色の数字を載せる

### 台帳（行とまとまり）

一覧は、`--bg` の上に `--border` の罫線で区切った行として直接並べます。行ごとにも、まとまりごとにも面を作りません。まとまりには12 pxの見出しを付けます。

面（`--surface`、`--border` の枠、角丸）を使うのは次の場合だけです。

- ホームの「確認すること」の箱
- 照合の件数の枠
- 突き合わせの伝票
- シート、ダイアログ、下部に固定する帯

### 1行リスト

```text
[アイコン 34px]  店名（15〜16px・500）          −¥3,284（15px・600・等幅）
                 補足（12.5〜13px・muted）
```

- 行の高さは最小56 px（設定の行は52 px）。行全体をタップできるようにする
- 長い店名は1行で省略記号にする。補足は1行にまとめる
- 詳細へ進む行には右端に「›」を付ける。値がある時は「›」の左に補足の色で値を書く（例：「予算 ¥120,000/月 ›」）

### 帳簿の行で組む入力

支出・収入・振替・レシートの入力は、入力欄の箱を並べず、1項目を1行にして罫線で区切ります。

```text
金額      ¥1,080                                ← 30px・等幅
店名      カフェこもれび
日付      10/18（日）              (今日) (昨日)
カテゴリ  外食  前回と同じ              すべて ›
支払元    PayPayカード                        ›
時刻・メモ  任意                               ›
品目      分けない（品目・値引き・税額）       ›
くり返し  しない（毎月・毎週・毎年にすると定期登録） ›
```

- 行は3列にする。左に項目名（幅4.6 em、13 px、`--muted`）、中央に値（16 px）、右に操作（›、日付のボタン、状態の表示）
- 行の高さは最小52 px、金額の行は64 px
- 入力中の行は、下の罫線を `--primary` の2 pxの線にする。箱の枠は付けない
- 入力のエラーは、その行の下線を `--danger` にし、行のすぐ下に `--danger` の文字で理由を書く
- 未入力の任意項目は、値の位置に「任意」等を `--muted` で書く
- 項目名は `<label>` として値の入力欄と結び付ける。見た目が文字だけでも、入力欄としての読み上げ名を失わない
- 選ぶ項目（支払元、カテゴリの「すべて ›」など）は、押すと下からシートを開いて選ぶ
- カテゴリの行の初めの値は、同じ種類（支出・収入）で前回使ったカテゴリにし、値の右に「前回と同じ」を `--muted` で添える。前回がない時、または前回のカテゴリが非表示・削除済みの時は空欄にする
- レシートで品目がある時は、金額の行の右の列に、品目と値引きの合計との照らし合わせを小さく書く。合っていれば `--success` の「✓ 一致」、合わなければ `--warning` の「△ 要確認」だけにし、説明の文は添えない
- レシートで品目がある時は、カテゴリの行は選ぶ欄にしない。「品目ごと」の札と、カテゴリ別の小計（色の点・名前・金額）を表示し、押すと品目一覧へ移る

### 状態の表示

- **件数の枠**（照合の上部）：1つの面を3列に区切り、要確認・記録なし・照合済みの記号・状態名・件数を並べる。要確認と記録なしは `*-soft` の背景にし、照合済みは背景を付けず数字だけ `--success` にする
- **「済」の印**：直径26 pxの円に1.5 pxの `--success` の線、中に太字の「済」。少し傾ける（−10°）。照合済みの件数の行に添える
- **確認することの箱**（ホーム）：`--surface` の面に、見出し・件数・最大3件の行を入れる
- **警告の帯**（反映の失敗）：`--danger-soft` の背景に、記号、太字の要点、補足の文、再試行のボタンを並べる
- **行の補足**：記号と短い文を、状態の色で書く（例：「△ 金額が¥50違います」）。記号は状態の `-soft` の小さな円に載せる
- **バッジ**：数字だけを出す場合は、読み上げ名に意味を含める

### 突き合わせの伝票

要確認の詳細では、明細と記録を1枚の伝票の上下に並べます。

- 上半分に明細、下半分に記録を置き、間をミシン目（`--border-strong` の破線と、左右の半円の切り欠き）で区切る
- 日付・店名・金額を同じ順に並べる。違う値は `--warning-soft` の背景に `--warning` の文字にする。同じ値には「同じ」を `--muted` で添える
- 「同じ支出として処理」を押したら、伝票の右に大きな「済」の印（直径96 px）を0.2秒で押す

### 読み取り中

写真から読み取っている間は、何をしているかを3つの段階の行で示します。画面の構成は[UX](UX.md#読み取り中)に定めます。

```text
[撮った写真（走査線が上下に動く）  ○ 読み取り中]
✓ 写真を保存しました       この端末に。読み取れなくても消えません
◌ 文字を読み取っています   10秒ほどかかります     ← 回転する印
○ 品目をカテゴリに分けます                         ← 点線の丸
金額  ▭▭▭▭▭                                      ← 仮の帯
店名  ▭▭▭▭▭▭▭
```

- 写真の上に、`--primary` の走査線と、`--text` の地の小さな札「読み取り中」を重ねる
- 段階は、終わったもの（✓、`--primary-soft` の円）、進行中（回転する印）、まだのもの（`--border-strong` の点線の円）で示す
- まだ読めていない欄は、`--sunken` のゆっくり光る帯にする。分類が終わっていない品目のカテゴリも同じ帯にする
- 主要ボタンは押せない状態にし、文言で状態を書く（「読み取り中…」）。下に「待たずに手で入力する」を文字のボタンで置く
- 読み取れなかった時は、段階の行を `--danger` の「!」にし、写真が残っていることと次にできることを書いた `--danger-soft` の帯を出す。帯の中に補助ボタン「撮り直す」を置き、主要ボタンは「もう一度読み取る」、その下に文字のボタン「手で入力して続ける」を置く
- キャラクターや経過秒数は表示しない
- 画面に `aria-busy` を付け、段階が変わるたびに `aria-live` で読み上げる

### 品目の行

- 閉じた品目は、品目名・カテゴリの札・金額を1行に並べる
- カテゴリの札は、カテゴリの色の点と名前を `--border` の枠で囲む。AIの提案でまだ確定していないものは、枠を破線にして名前の後に「?」を付ける
- 開いた品目は、左端に3 pxの `--primary-soft` の線を引き、品名・金額・カテゴリの入力と、分類の理由（「いつもの分類」等）、削除を出す
- 品目一覧の上には、合計の行（「¥3,284 ✓ 品目と一致」）と、カテゴリ別の小計の帯を置く

### ボタン

| 種類 | 見た目 | 使う場所 |
| --- | --- | --- |
| 主要 | `--primary` で塗る。高さ52〜54 px、横幅いっぱい、`--radius-lg` | 1画面に1つ（登録する、同じ支出として処理） |
| 補助 | `--surface` の面に `--border` の枠 | 明細を取り込む、バックアップを読み込む |
| 文字 | 背景なしで `--primary` の文字 | 戻る、キャンセル、すべて、別の支出です |
| 破壊的 | `--danger` の文字。塗らない | 削除する |

- 押せない主要ボタンは `--sunken` の背景に `--muted` の文字にし、何を待っているかを文言で書く
- 作業画面の主要ボタンは、画面下の固定の帯（`--surface`、上に罫線）に置く
- 記録の種類を選ぶシートの「レシートを撮る」は、塗らずに `--surface` の面と `--border` の枠にする。シートの中でいちばん大きくし、カメラのアイコンだけを `--primary` で塗った52 pxの角丸の四角に白で載せる。下に見える「＋追加」と塗った面が重ならないようにするため

### 選択

- **切り替え**（全体と品目一覧、記録の種類の絞り込み）：`--sunken` の下地に、選択中だけ `--surface` の面を載せ太字にする
- **丸いボタン**（今日・昨日、帳簿の行の中の短い選択）：見た目の高さ36 px、タップできる範囲は44 px以上。選択中は `--primary-soft` の背景、`--primary` の2 pxの枠と文字、✓を付ける
- **カテゴリを選ぶシート**：「すべて ›」から開く。4列、高さ64〜68 pxのボタンに、色付きのアイコンと名前（2行まで）を書く。選択中は2 pxの `--primary` の枠、`--primary-soft` の背景、太字にする。最後に「＋追加」を置く。読み上げでは単一選択のラジオボタン（`role="radiogroup"` / `role="radio"`、`aria-checked`）として扱う

選択中であることは、色だけでなく枠・✓・`aria-pressed` / `aria-checked` でも示します。

### シートとダイアログ

- ＋追加は画面下から出るシート（`<dialog>` を `showModal()` で開く）にする。上部につまみ、見出し、閉じるボタンを置く。開く時に下から0.2秒でせり出し、つまみや見出しを下へ80 px以上動かすと閉じる
- 記録の種類を選ぶシートは、上に「レシートを撮る」を横幅いっぱいで置き、その下に「写真から」「支出を手入力」「収入」「口座間の振替」を2列で並べる。各項目は名前と短い補足の2行にする
- カテゴリ・口座の途中追加は、中央の小さなダイアログにする
- どちらも背後を `--scrim` で暗くし、フォーカスを中に閉じ込める

### 支出の内訳（帯グラフ）

- 横に長い帯（高さ12 px、角丸6 px）を、カテゴリごとの割合で区切る。区分の間に2 pxのすき間を空ける
- 区分は最大4つ（上位3カテゴリとその他）。左から大きい順に並べる
- 下に2列の凡例を置き、色の点・カテゴリ名・割合を書く
- 読み上げ用に、全体の内訳を文にした `aria-label` を付ける
- レシートの品目のカテゴリ別小計にも、同じ帯（高さ8 px）と、金額を書いた凡例を使う

### 予算の進み具合（日の目盛り）

ホームの予算は、月の日数分の細い目盛り（1日1本、高さ26 px、間2 px）で示します。

- 塗る本数は「使用額 ÷ 予算額 × 月の日数」（月の日数が上限）。今日の位置までは `--primary`、今日を超えた分は `--warning` で塗る
- 今日の位置に `--text` の縦線を引き、下に「今日18日 · 目安より ¥12,753 多め」のように目安との差を文字で書く。目安は「予算額 × 経過日数 ÷ 月の日数」
- 予算を超えた時は目盛りをすべて `--danger` にし、「¥3,000超過」のように文字でも示す
- 目盛りは全体予算（カテゴリ別の内訳がある月も、その合計の全体予算）に対して描く。予算が0円の月は目盛りを描かず、使用額と超過額だけを文字で示す
- 目盛りの上に「予算 ¥120,000」「残り ¥37,570 ›」を書く。読み上げ用に、使用額・予算額・残り・目安との差を文にした `aria-label` を付ける

## アイコン

- 24 pxの格子に描いた線のアイコンをinline SVGで使う。線の太さは2 px、端と角は丸くする。色は `currentColor` にする
- 絵文字をアイコンとして使わない
- アイコンだけで意味を伝えない。文字を添えるか、読み上げ名を付ける
- 同じ意味には同じアイコンを使う（例：要確認は三角、記録なしと失敗は「!」、照合済みはチェックと「済」の印）

### ホーム画面のアイコン

「カードとレシート」の案Bを採用しています。クリーム色（`#FFF3DD`）の地に、緑のカードと白いレシートを重ね、レシートに緑のチェックを描きます。あんず色への変更に合わせて色を見直すかは未定です。

- iOS用に180×180 pxのPNG（`apple-touch-icon.png`）を用意する。iOSはSVGのアイコンを安定して表示しないため。iOSが角を丸めるので、角丸と透明部分を付けない
- manifestには192 px、512 px（角丸・角は透明）と、`purpose: "maskable"` の512 px（角丸なし）を用意する。maskable版は、絵柄を縮めて中央80%の円（安全域）に収める
- アイコンは `apps/pwa/scripts/render-icons.mjs` で `apps/pwa/public/` に生成する（`corepack pnpm --dir apps/pwa icons`）。絵柄を変える時はこのスクリプトを直して作り直し、PNGを手で編集しない
- `theme-color` は、ライトとダークでそれぞれの `--bg` に合わせる

## ダークモード

- 端末の外観設定（`prefers-color-scheme`）に合わせて自動で切り替える。アプリ内に切り替えの設定は置かない
- 切り替えはトークンの値の差し替えだけで行う。画面ごとにダーク用のCSSを書かない
- 写真やレシートの画像は暗くしない

## レスポンシブ

スマートフォンを基準にします。CSSはスマートフォンの見た目を土台に書き、PC用の違いは `min-width: 1024px` のメディアクエリ1つにまとめます。画面ごとに別のブレークポイントを作りません。1023 px以下（タブレットの縦向きを含む）は、スマートフォンと同じ表示です。

### PC（1024 px以上）

画面構成は[UX](UX.md#pcでの表示)に定めます。見た目の決まりは次のとおりです。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--sidebar-width` | 240 px | 左のサイドナビの幅 |
| `--content-max` | 760 px | 記録・照合・設定・入力の本文の最大幅 |
| `--content-wide` | 1080 px | ホームの2列の最大幅 |

- **サイドナビ**：画面の左に固定し、`--surface` の面と右の罫線で分ける。上からアプリ名（18 px・700・`--primary`）、「＋ 記録を追加」、ホーム・記録・照合を並べ、設定は一番下に置く。各タブはアイコン（24 px）とラベル（16 px）を横に並べ、高さ48 px。選択中は `--primary-soft` の背景と太字にする。照合のバッジはラベルの右端に置く
- **「＋ 記録を追加」**：サイドナビの中で唯一塗るボタン。`--primary` で塗り、高さ48 px、`--radius-lg`、浮いて見える影を付ける
- **本文**：サイドナビの右に、上下左右32 pxの余白を取って中央に置く。下部ナビの高さ（`--nav-height`）は0にする
- **ホーム**：2列のグリッド（列の間24 px）。左に今月の支出・予算の目盛り・確認することの箱・最近の記録、右に支出の内訳を置く
- **入力の主要ボタン**：画面下に固定する帯は、角を丸めた面（`--radius-xl`、`--border` の枠）にし、ボタンは右寄せで幅240 px以上にする
- **記録の種類を選ぶシート**：画面中央のダイアログ（幅520 px、`--radius-xl`）として開く。つまみは表示せず、マウスでのドラッグでは閉じない。開く時は0.2秒で少し下からフェードインさせる
- **ホバー**：マウスで操作する時だけ、1行リストとナビに `--sunken` の背景を付ける。ホバーは押せることの補助で、ホバーしないと見えない操作は作らない
- 一覧と詳細を左右に並べる2ペイン表示は、まだ使わない（[UX](UX.md#pcでの表示)の今後の検討）

## 動き

アニメーションは、状態の理解を助ける時だけ200 ms程度で使います。

- シートの出入り
- 詳細や品目の開閉
- 保存完了の表示、「済」の印を押す動き
- 読み取り中の走査線・回転する印・仮の帯、取り込み中の表示

装飾のための長い演出やキャラクターは使いません。`prefers-reduced-motion` が有効な時は、すべての動きを止めます。止めた時も、文言で状態が分かるようにします。

## 禁止事項

- 1件ごとのカード、同じ情報の重複表示
- 一覧のまとまりを面で囲うこと（面を使う場所は[台帳](#台帳行とまとまり)に挙げたものだけ）
- 色コードや任意の余白の直接指定
- inline styleの乱用
- 同じ役割のボタンや入力欄を複数の実装で作ること
- 状態の色（success・warning・missing・danger）をボタン・選択中・リンクに使うこと
- hoverに頼る操作
- 44 CSS pxより小さいタップ領域
- 絵文字のアイコン、アイコンだけのボタンに読み上げ名がないこと
- AIが出した値を、確認なしに正しいものとして見せること

## デザインを決める順序

1. 情報の構造
2. 利用の流れ
3. ワイヤーフレーム（[UX](UX.md)）
4. 部品の構成
5. 文字と余白
6. 意味の色
7. 細かな装飾

見た目を磨く前に、主な利用者が迷わず操作できるかを確かめます。
