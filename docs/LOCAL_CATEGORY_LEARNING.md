# カテゴリ修正履歴による分類

Issue #79では、利用者が確定したレシートのカテゴリを端末内に保存し、安定した履歴を次回の分類に利用する。

## 履歴と判定

店舗名と品目名は既存の店舗名正規化と同じ方法で、全角・半角、英字の大小、空白を揃える。意味の異なる商品名をまとめる曖昧な照合は行わない。

同じ店舗名または品目名について、同一カテゴリの確定が異なるレシートで3件以上あり、全履歴に占める一致率が80%以上なら自動適用する。閾値は `src/lib/category-learning.ts` の定数に集約している。同じレシートの再保存や編集は現在の確定内容を置き換え、票数を増やさない。同一レシート内の同名品目も1票として扱う。カテゴリが競合した品目や削除済みカテゴリの履歴は、一致率の分母に残す。

品目の分類を店舗の分類より優先する。複数カテゴリが混在したレシートの履歴がある店舗には、店舗だけで分類するルールを適用しない。利用者は自動適用後も通常の登録・編集画面でカテゴリを変更できる。

履歴は現在の利用者の `correction-audit` レコードに保存する。登録後の編集では、家計簿への更新を確認した後、レシートと分類履歴を同じローカル保存処理で更新する。既存のActualの取引ルールを変更したり、一括再分類したりはしない。

## AIとの境界

Geminiは画像から店名・品目・金額を抽出する。分類履歴で全品目が確定した場合、Jevによるカテゴリ分類は呼ばない。部分的に未分類なら、その品目だけをJevへ送る。選択肢には現在の支出カテゴリのIDと名前を使うため、利用者が追加したカテゴリにも対応する。

ブラウザからAI Gatewayへは、読取結果の利用権限を検証するために元のレシート情報と未分類品目の位置を送る。Gatewayは検証後、未分類品目だけをJevの入力に含める。学習履歴、票数、学習ルールを外部APIやクラウドの計測情報に送らない。

Jevの回答は、その読取結果に対する生の分類結果として別途保存する。再表示時には現在の学習ルールを先に適用し、残りだけに保存済み回答を利用する。同じ読取結果で分類APIを重複利用しない。新しく画像を読み取り直した場合は、この回答を破棄する。

削除されたカテゴリは候補から除外する。安定した分類がない場合はJevで提案し、通信失敗や低い確信度では手動選択に戻る。1回の分類は元の先頭30品目までを対象とする。支出カテゴリが0件または100件を超える場合は手動で選択する。従来の店舗対応表は、品目がなく、その店舗の新しい分類履歴もないレシートだけで利用する。

## 分類ルールの管理

設定の「分類ルール」では、履歴から現在導出できる品目・店舗ルールの根拠件数と一致率を表示する。利用者はルールを無効化し、適用カテゴリを上書きし、または学習履歴を残したままルールの適用を削除できる。削除済みルールは履歴からすぐ復活しない。すべての変更をリセットすると、履歴から再計算する。

上書き・無効化・削除抑止は `app-settings` レコードに端末内保存し、`.kmb` のportable backup / restoreに含める。ルール名や内容をAI Gatewayやtelemetryへ送信しない。手動で新しい分類Ruleを作る機能はこの画面には含めない。

分類提案を適用した時は、実際に使った店舗・品目Rule、カテゴリ名、根拠件数、一致率をレシート記録へsnapshotとして保存する。レシート詳細の「分類の理由」から、この適用時点の根拠を確認できる。後から学習履歴が変わってもsnapshotは更新しない。snapshotを持たない既存レシートには理由を表示せず、現在の履歴を過去の適用根拠として使わない。snapshotはportable backup / restoreに含める。

## バックアップと確認

分類履歴と読取結果に対応するJev回答は、既存の持ち運び可能なバックアップに含める。復元時に型と構造を検証する。新しいIndexedDBの保存領域や移行処理は追加していない。

単体テストでは、件数・一致率、編集による票の置換、混在店舗、独自カテゴリ、削除カテゴリ、無効化・上書き・削除抑止とreset、分類根拠snapshotのbackup / restore、未分類品目だけの分類、保存済み回答の再利用を確認する。ブラウザテストは人工の画像とAI応答を使用し、375px幅で登録、分類ルールの確認・変更、旧レシートに対する根拠の非表示、適用理由の表示、backup / restore、オフライン閲覧を確認する。実際の外部AI応答とiPhone実機は検証していない。

PWAとAI Gatewayの契約を同時に変更しているため、リリース時には両方を更新する。Gatewayはカテゴリや品目位置を指定しない従来の入力も受け付ける。このPRではデプロイを行わない。
