# 暗号化同期版と一時復元の接続

Issue #143の端末側接続の最初の段階。#38の暗号化形式・鍵の保護と復旧処理を再利用し、家計簿全体の `.kmb` を暗号化した版として受け渡す。暗号化処理や保存先Providerを別実装しない。

`prepareEncryptedSyncVersion()` は取得済みの一貫した `.kmb` を検証してから暗号化する。家計簿ID、世代（1以上）、版ID、親版IDは呼出し側が決める。暗号文を4 MiB以下の転送チャンクに分け、番号・サイズ・SHA-256・暗号文全体のサイズを返す。取得関数が返すのは暗号文だけで、平文、復旧コード、復号鍵は目録に含まれない。

転送チャンクは暗号化形式のチャンクと別物。形式のヘッダー・目録・認証タグの増分により、256 MiBの平文は最大65個の転送チャンクになる。暗号文全体上限は256 MiB + 16 KiBで、#171の初期設定（転送上限128個、単一チャンク4 MiB + 16 KiB）以内に収まる。保存先との通信、版の比較付き公開、再送の要求IDは本段階に含めない。

`decryptPortableSyncVersion()` には、選択した版から別途確定した識別情報と非抽出の家計簿鍵を渡す。ダウンロードしたヘッダーだけから期待値を決めない。目録のサイズ・連続した番号・総数を検証し、取得した各チャンクのサイズとhashを照合する。SHA-256だけを真正性の根拠にせず、全暗号化チャンクのAES-GCM認証と `.kmb` の形式・schema・参照検証を終えてから平文を返す。

`restoreEncryptedLocalBackup()` はこの検証を終えた平文だけを既存の `restoreLocalBackup()` へ渡す。復元先は空の別profile/Actual保存先で、元データに直接読み込まない。#58の不完全復元マーカーによる再試行停止と、復元成功後だけのprofile切り替えを維持する。

## 未実装の境界

これらは同期コーディネーター向けの接続APIで、通常の設定画面に同期を追加せず、クラウドへ送信しない。鍵の保存・参加・失効後の鍵切り替え、家計簿全体の排他制御、永続的な変更番号、送信状態、切り替え直前のprofile/基準版の再確認と異常終了後の復旧は後続工程。排他制御なしでliveの家計簿を書き出し・取り込む呼び出しを追加しない。

暗号文のhash検証は転送チャンク単位で読み込むが、返却Blobと既存 `.kmb` 検証/Actual復元は全体のメモリーを保持し得る。4 MiBだけの最大メモリー使用量を保証しない。iPhoneの大容量復元、実R2送受信、実機の異常終了試験は未確認。Issue #143全体の完了として扱わない。

## 検証

合成データで、新端末の復旧鍵による復号、4 MiB境界、別版/親/家計簿/世代、目録不正、取得失敗・欠落・並べ替え、hashを再計算した暗号文改ざん、誤鍵、認証済みだが不正な `.kmb` を検証する。一時復元の接続では、拒否時にActual importを呼ばず、元profileを維持することを確認する。新しいChromium contextでは元端末の鍵や保存領域を引き継がず、復旧コードと保護鍵だけでportable版を復号する。
