# 明細CSV形式の確認記録

この文書は、確認できた各社の公式情報と、取り込みadapterが安全に対応できる範囲を記録します。ヘッダーなし形式では、providerを利用者が選択したうえで、metadata・明細・集計行の全体構造を厳格に確認します。未知のレイアウトからproviderや列の意味を推測しません。

## 三井住友カード（Vpass）

- **確認日:** 2026-10-02
- **公式情報:** [ご利用明細の見方・保存方法](https://www.smbc-card.com/mem/oshiharai/meisai_about.jsp)、[WEB明細の項目説明](https://www.smbc-card.com/mem/oshiharai/pop/wm_setsumei.jsp)、[カード利用明細の説明](https://www.smbc-card.com/mem/hitotoki/card_use/detailed_statement.jsp)
- **確認できたこと:** Vpass WEB明細はCSVで保存できます。[三井住友カード公式案内 (2026/10), WEB明細](https://www.smbc-card.com/mem/oshiharai/meisai_about.jsp) Issue #109に記録されたfresh export 2件では、CP932で復号でき、headerなし、先頭の3列metadata、7列の明細、最後の7列summaryという構造でした。このexportの観察結果は[Issue #109 (2026/10), fresh export確認](https://github.com/RyoyaYahagi/KakeiMatch/issues/109)に記録されています。文字コードはこの2件で確認したもので、公開CSV仕様による保証ではありません。
- **metadata:** 実装は先頭行を厳密に3列と判定します。内容は会員・カード情報を含むため、parse結果、headerSignature、canonical明細、エラー表示やログへ転記しません。headerSignatureには固定値 `smbc-vpass-cp932-v1` を使います。[実装 (2026/10), Vpass解析](../src/lib/statement-parser-core.ts)
- **summary:** 実装は最終行の列1〜5と列7が空、列6が正の整数円であることを要求します。明細候補はその前に1行以上あり、すべて厳密に7列でなければファイル全体を拒否します。[実装 (2026/10), Vpass解析](../src/lib/statement-parser-core.ts)
- **通常購入:** Issue #109に記録されたfresh export 2件で確認した通常1回払いは、列1が有効な `YYYY/MM/DD`、列2が空でない利用先、列3が正の整数円、列4・5が全角 `１`、列6が正の整数円かつ列3と同額、列7が空でした。[Issue #109 (2026/10), 通常購入の観察](https://github.com/RyoyaYahagi/KakeiMatch/issues/109) 実装はこれらをすべて満たす行だけを購入として読み込みます。`usedDate=列1`、`merchant=列2`（原文を保持）、`amountYen=列3`、`paymentMethod=1回払い` とします。[実装 (2026/10), Vpass解析](../src/lib/statement-parser-core.ts)
- **summary整合性:** 実装は全明細行が通常購入として受理された場合に限り、列6の合計がsummaryの列6と一致することを要求します。要確認行がある混在ファイルでは、要確認行の金額の意味が未確定なので合計照合を行いません。[実装 (2026/10), Vpass解析](../src/lib/statement-parser-core.ts)
- **要確認の実装方針:** 分割・リボ・2回・ボーナス・キャッシング、返金・取消、年会費・手数料、海外利用など、通常購入の厳密条件を満たさない7列行は購入にしません。利用先に「年会費」「手数料」「キャッシング」「利息」「遅延損害金」「取消」「キャンセル」「返金」「返品」「ボーナス」「海外利用」の語が明記されている場合も、列が一致していても要確認にします。これらの語が実データ上の行ラベルとして確認されたという意味ではなく、明確な特殊語を含む利用先を誤って購入にしないための保守的な実装規則です。行番号と一般的な理由だけを端末内の取込情報へ保存して表示します。明細値はAIやサーバーへ送りません。[実装 (2026/10), Vpass解析](../src/lib/statement-parser-core.ts)
- **対応状態:** 通常の1回払い購入だけを対応します。metadata・明細・footerの全体signatureを検証し、列数だけでは形式を判定しません。未知の構造、summary不正、通常購入のみのファイルで合計不一致の場合は拒否します。fixtureはすべて合成データで、fresh exportの個別情報は保存していません。[実装 (2026/10), Vpass解析](../src/lib/statement-parser-core.ts)

## 楽天カード

- **確認日:** 2026-09-29
- **公式情報:** [楽天e-NAVI CSV形式のダウンロードについて](https://www.rakuten-card.co.jp/e-navi/p/rc/e-navi/statement/popup2.html)
- **確認できたこと:** 請求確定分のWEB明細を請求月単位でCSV出力できます。CSVはPC版楽天e-NAVIから取得します。1件の明細が2行表示される場合があり、その場合CSVにも2行で出力されます。利用店舗名・商品名が途中で切れることや、一部文字が文字化けする場合も公式説明にあります。加えて、ユーザー提供の実exportを読み取り専用で調べ、列構造を確認しました。実データ値は保存・公開していません。
- **文字コード:** 調べた実exportはUTF-8 BOM付きでした。公式公開情報では文字コードを確認できていません。
- **期待ヘッダー（列順を含む）:** 実exportの先頭行で確認した11列は `利用日`, `利用店名・商品名`, `利用者`, `支払方法`, `利用金額`, `手数料/利息`, `支払総額`, `9月支払金額`, `当月請求額`, `10月繰越残高`, `新規サイン` です。月名の部分は請求月により変わるため、固定列名としての完全一致署名ではありません。公式CSVページ本文はこの列名一覧を掲載していません。
- **日付の意味:** 公式の明細案内は「利用日」と説明します。CSVの先頭列名も「利用日」です。ただし、加盟店からの売上データ到着時期により請求月が遅れる場合があり、利用日だけで請求対象月を定められません。
- **金額の意味:** 公式説明では「利用金額」は現金価格、「当月請求額」は分割支払額（リボ払いでは弁済金）です。実exportではこれらが異なる行があり、選択した支払方法カテゴリでは両列とも値がありました。したがって、金額列を一律に選んでpurchase額へ変換する規則は確定できません。月名付きの列も存在します。金額の符号と返金時の扱いは確認できていません。
- **返金・特殊行:** 公式ページは1件の明細が複数行になる場合があると明記します。調べた実exportにも列2だけが埋まる継続行と、列1から7までが埋まり残りが空の部分行がありました。継続行・部分行の意味や対応関係を公式資料で確認できないため、行を独自に結合したり、通常取引として取り込んだりしてはいけません。キャンセル・返金のCSV上の表現も確認できません。
- **対応状態:** unsupported。実exportから文字コードと列構造は確認できましたが、意味が不明な継続行・部分行、金額列の選択規則、返金・特殊行を安全に分類できません。実データはfixtureやリポジトリに保存していません。完全に合成したsampleと公式情報で意味を確認するまでadapterを有効にしません。

## イオンカード

- **確認日:** 2026-09-29
- **公式情報:** [ご請求明細書（PDF・CSV）のダウンロード方法（暮らしのマネーサイト FAQ）](https://faq.aeon.co.jp/faq/show/226?back=front%2Fcategory%3Ashow&category_id=1&faq_id=20203&keyword=WEB%E6%98%8E%E7%B4%B0&page=8&site_domain=default&sort=sort_access&sort_order=desc)
- **確認できたこと:** AEON Payアプリおよび暮らしのマネーサイトから、請求確定月の請求明細書をダウンロードできます。FAQはPDF・CSVのダウンロード方法を掲げていますが、CSVの具体的な列定義は掲載していません。
- **文字コード:** 公式公開情報では確認できません。
- **期待ヘッダー:** 公開公式情報では列名一覧やCSVサンプルを確認できず、exact header signatureを確認できません。
- **日付の意味:** CSVに出力される日付列とその意味は公開仕様で確認できません。
- **金額の意味:** CSVの金額列と符号規則は公開仕様で確認できません。
- **返金・特殊行:** CSV上の返金、取消、分割払い等の表現は公開仕様で確認できません。
- **対応状態:** unsupported。新しいイオンカード個人向けexport、またはカード番号・氏名・住所・店舗などを完全に合成データへ置き換えたsampleが必要です。

## PayPay

- **確認日:** 2026-09-29
- **公式情報:** [取引履歴のダウンロードについて（PayPayヘルプ）](https://paypay.ne.jp/help/c0447/)、[取引履歴について（PayPayヘルプ）](https://paypay.ne.jp/help/c0141/)
- **確認できたこと:** 個人向け取引履歴をCSVでダウンロードできます。公式ヘルプはExcelでの読み込み文字コードとしてUnicode（UTF-8）を案内しています。CSVの正確なバイト形式にUTF-8 BOMが付くかは明記されていません。
- **文字コード:** UTF-8。UTF-8 BOMは実ファイルで確認するまでは仕様として断定しません。CP932 / Shift_JISは対応形式として確認できていません。
- **期待ヘッダー（列順を含む）:** `取引日`, `出金金額（円）`, `入金金額（円）`, `海外出金金額`, `通貨`, `変換レート（円）`, `利用国`, `取引内容`, `取引先`, `取引方法`, `支払い区分`, `利用者`, `取引番号`。adapterはこの13列の完全一致だけを受け付けます。
- **日付の意味:** `取引日` は取引日時で、公式例は `2024/06/03 11:28` です。日時の例から日付・時刻を分けて保持します。posted dateに相当する列は公開された項目一覧にありません。
- **金額の意味:** `出金金額（円）` と `入金金額（円）` は別列です。canonical金額は符号ではなく列と取引内容の組合せから正の整数円として作ります。海外出金金額は現地通貨額であり、円の支出額として使いません。小数の変換レートも円の支出額として使いません。
- **購入:** `取引内容` が公式例の `支払い` で、`出金金額（円）` が有効な正の整数、`入金金額（円）` が空またはゼロの場合だけpurchase候補にします。条件が崩れた行は拒否します。`取引番号` を `externalId` にします。
- **返金:** 公式ヘルプは「返金」を入金種別として定義し、返金取引がCSV履歴に含まれると説明しています。adapterは公式の種別名とCSV列を組み合わせ、`取引内容` が厳密に `返金`、`入金金額（円）` が正の整数、`出金金額（円）` が空またはゼロの行だけをrefundとして扱います。これは公式2ページからの限定的な推論であり、実際のexportでラベルと金額方向は未検証です。条件が異なる行は拒否します。
- **対象外:** PayPayの公式ヘルプは出金の種別に「支払い」「送金（譲渡）」「寄付」「銀行口座への出金」「チャージ取り消し」「支払い受付」「請求書払い」、入金の種別に「ポイント獲得」「受け取り」「チャージ」「返金」「給与」を列挙しています。支払い以外の入出金を支出にしません。特にチャージ、ポイント獲得、受け取り、給与などの入金は支出として登録しません。支払い以外で既知の種別を安全に識別できるCSV値がfixtureで確認できた場合に限りexcludedとし、未知の `取引内容` は拒否します。
- **特殊行:** 公式ページによると `取引番号` が `lp-` で始まる場合はPayPayポイント（期間限定）が付与された取引です。ポイント付与を購入として扱いません。ダウンロードには処理中・失敗・期間切れ・取消・超過利用の取引は含まれません。
- **対応状態:** headerと出金・入金フィールドの存在は公式一次情報で確認済みです。`支払い` と `返金` の上記の狭い条件を受け付け、その他の未確認表記は拒否します。実exportで返金・除外各種のCSV表記を追加検証してください。`取引番号` はexternal IDに使用します。

## 実装時の安全条件

- 取り込み画面で利用者にproviderを選択してもらい、そのadapterの完全一致headerだけを受け付けます。未知のheaderからproviderを推測しません。
- 公式仕様で確証のない行ラベル、金額符号、複数行の結合規則は推測しません。
- 既知の非支出行だけをexcludedとして記録できます。行単位の部分取込を明示的に定めたadapter（現時点ではVpass）では、認識済みの全体signature内の不確かな明細を要確認として記録し、安全な行だけを取り込みます。それ以外の形式で意味が分からない行や未知のfile layoutは拒否します。
- 三井住友カード、楽天カード、イオンカードを有効化する前に、新しいprovider exportまたは完全にsynthetic化したsampleを検証し、ここにheader、文字コード、日付・金額・返金・特殊行の意味を追記します。
- 明細データはGeminiやJevへ送信しません。
