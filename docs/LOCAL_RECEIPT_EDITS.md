# 登録した記録の編集

記録一覧やホームの行から登録済みレシートの詳細を開き、「編集する」を選びます。店名、購入日、時刻、合計金額、カテゴリ、支払元、メモ、品目と品目ごとのカテゴリ、値引き・調整、税額を修正できます。品目と画像は詳細で必要なときだけ開きます。

編集には新規レシート登録と同じ入力フォームを使います。キャンセルしても変更途中の下書きを端末に保持します。保存が成功すると、追加の確認画面を挟まず詳細へ戻ります。AIでの読み取り直しは新規登録に限ります。

金額やカテゴリ配分は通常コードで検証します。複数カテゴリを設定する場合、品目と対象を指定した値引きの合計がレシート総額と一致することが必要です。カテゴリを分ける取引を通常取引へ変更する場合も、その逆の場合も、同じActual親取引IDと登録識別子を維持します。

## 手入力の購入内容と値引き

新しい手入力支出も、レシート画像を持たない支出として同じ品目・値引きの保存処理を使います。「購入内容（任意）」を開くと品目名、金額、カテゴリを追加できます。品目を入力せず、合計金額だけでも登録できます。登録済みの詳細・編集やバックアップ復元後も品目を確認できます。以前の手入力で登録した取引は、従来の編集画面で編集します。

値引き額は正数で入力します。「100円引き」には `100` を入力し、保存値は `amountYen = -100` とします。加算は「その他の調整（加算）」を選びます。既存のバックアップに含まれる負数の値引きも、正数の入力欄へ表示します。保存する品目・値引きの構造は変更しません。

品目の削除ボタンはカテゴリの下に表示します。入力欄から離れても品目の編集欄を自動で閉じません。削除対象に紐づいた値引きは対象指定を解除します。他の品目と利用者が入力した合計金額は保持します。合計と購入内容が一致しない場合は差額を示し、複数カテゴリへの配分が一致しない登録は止めます。

レシート画像を選択すると、画像の直後に「AIで読み取る」を表示します。読み取り済みの場合は「再読み取り」とし、利用枠の消費と入力の置き換えを確認してから実行します。最終登録ボタンだけを主要操作とし、読取ボタンは補助操作として表示します。

## 保存と失敗からの回復

Actual BudgetとKakeiMatchの保存領域は異なるため、両者を1つのデータベース操作で更新することはできません。編集前後の構造化値、対象、変更操作の識別子、日時を先に端末内へ保存します。その内容で既存Actual取引を更新し、保存された値を読み直して確認します。その後にレシートの確定値と変更履歴をKakeiMatchの同じデータベース操作で確定します。

Actual更新後に端末内情報の確定が失敗した場合、前の確定値と保存待ちの変更内容を残します。編集画面では変更内容を固定して、同じ内容を再試行します。再試行は同じActual取引を更新するため、追加取引は作りません。保存待ちの変更と完了した履歴は `.kmb` に含まれます。過去の変更履歴は新しい編集で上書きしません。

別の画面で既に変更されたレシートへ古い画面から保存しようとした場合は、最新の内容を開き直すよう案内します。収入・支出の手入力と振替の編集にも、端末内の変更前後の履歴を追加しています。履歴はCloudflareへ送信しません。

Actual 26.9.0の公開 `updateTransaction` は内部更新の完了を待たないため、編集用adapterでは初期化時に取得する `transactions-batch-update` の完了を待ちます。レシートの分割では、親と必要な全子取引の変更を一括で渡します。利用中の支払元と支出カテゴリを検証し、保存後に金額・日付・店名・カテゴリ配分・登録識別子を確認します。

## 確認

合成データだけを使うブラウザーテストで、登録・詳細表示・編集・再読込・バックアップ復元・オフライン編集を確認します。

```sh
PWA_E2E_URL=http://127.0.0.1:5173 corepack pnpm --dir apps/pwa test:receipt-edits-e2e
```

手入力の品目・値引きは `test:manual-items-e2e`、画像ありの入力は `test:receipt-items-e2e` で確認します。
