# Product

## 目的

KakeiMatchは、家計簿への入力と、後日届くクレジットカード・決済明細との照合作業を楽にする家族向けWebアプリです。

現在の手作業では、レシートを家計簿へ登録した後、カード明細と一件ずつ突き合わせ、金額差や記録漏れを確認する必要があります。KakeiMatchは、一致する取引を自動で処理し、人間には判断が必要な取引だけを提示します。

## 想定ユーザー

- 親1人を主利用者とする
- 開発者本人も利用する
- 将来、兄弟など他の家族が利用する可能性がある
- 利用者ごとにログインアカウントを分ける
- **MVPでは各ユーザーは自分の家計簿だけを閲覧・操作できる**
- 家族間の家計簿共有は将来機能とし、MVPでは実装しない

## MVPの中心体験

### 1. レシートから支出を登録する

1. スマートフォンでレシートを撮影する
2. Geminiが店名、日付、合計金額、商品などを抽出する
3. 支出カテゴリを推定する
4. 必要な場合だけユーザーが修正する
5. 家計簿へ登録し、レシート画像も保存する

### 2. 明細を取り込んで照合する

1. カード会社・決済サービスから取得した明細をアップロードする
2. ログイン中ユーザーの家計簿の既存取引と候補を照合する
3. 高信頼の一致は自動処理する
4. 曖昧なものだけ「要確認」にする
5. 対応する記録が見つからない明細は「記録なし」として提示する

- レシート撮影

- Geminiによる構造化抽出

## 重要な設計原則

### 人間が確認する件数を減らす

OCR精度100%を目標にしません。目的は、正しく自動処理できる取引を人間に見せず、確認が必要な取引だけに注意を向けられるようにすることです。

### 未照合を不正利用と断定しない

対応するレシートが存在しない理由には、レシート紛失、オンライン決済、利用日と計上日の差、返品、予約・仮売上などがあります。「不正利用」ではなく「確認が必要」と表現します。

### AIと決定的ロジックを使い分ける

AIをすべての判断に使用しません。

- Gemini: レシート画像の理解・構造化
- Jev: 曖昧なカテゴリ分類
- 通常コード: 金額、日付、店舗などを使った照合・重複判定・状態遷移

### OSSで解決済みの問題を作り直さない

家計簿の基盤はActual Budgetを利用し、KakeiMatchは家族向けUX、レシート入力、AI分類、明細照合に集中します。

### 個人データを混ぜない

MVPでは、あるユーザーのレシート・支出・明細・照合結果が別ユーザーに見えないことを必須要件とします。

## 基本カテゴリ（暫定）

- 食費
- 日用品
- 交通
- 医療
- 衣服
- 娯楽
- 水道・光熱
- 通信
- その他

カテゴリは固定仕様ではなく、利用開始後に調整できる設計にします。

## MVPではやらないこと

- AIによる不正利用の断定
- 銀行・カード会社への自動ログイン
- スクレイピングによる明細取得
- 家族間の家計簿共有
- 高度な資産運用・投資管理
- 家計簿機能の全面再実装
- Actual Budget本体のfork
- 複雑な会計・経費精算機能
- 初期段階での過剰な通知や分析機能

## 成功指標

第一の成功指標は機能数ではなく、現在の手作業がどれだけ減るかです。

- レシート登録に必要な操作数
- 自動照合率
- 明細100件あたり人間が確認する件数
- OCR結果の手修正率
- 1か月の家計簿・照合作業時間
