# カテゴリと支払元の管理

設定の「カテゴリ」「支払元」から管理画面を開きます。一覧の行を押すと詳細を確認でき、「編集する」から名前や口座の種類を変更します。管理画面を開いている間は、バックアップやAIアカウントの設定を表示しません。

## カテゴリ

支出カテゴリと収入カテゴリは切り替えて表示します。追加時の種類は開いている一覧に従います。Actual Budgetの `is_income` を正本とし、収入カテゴリはレシートからの支出登録には表示しません。利用者が作った独自カテゴリも支出登録で選べます。基本の支出カテゴリは家計簿ごとの初回利用時に自動で用意し、以後は利用者の名前変更・非表示・削除を尊重して自動再作成しません。

各カテゴリは名前変更、非表示・再表示、未使用の場合の削除に対応します。グループ名と表示状態は詳細で確認できます。Actual側でグループ全体が非表示の場合、カテゴリだけの再表示では一覧の利用候補に戻らないことがあります。グループ編集は今回の対象外です。

削除は確認ダイアログを経て実行します。既存の取引行があれば削除を中止し、非表示を案内します。閉じた口座、未来日の取引、分割取引の子の行も利用確認の対象です。別カテゴリへの一括付け替えは実装していません。

## 支払元

銀行口座・クレジットカード・現金・その他 / 未分類の種類ごとに一覧を表示します。追加フォームでは名前と種類を入力し、残高0円の口座を作成します。種類は後から変更できます。既存口座に種類の記録がない場合は「その他 / 未分類」として表示し、名前から推測しません。詳細では名前、種類、状態、差引額、取引行の件数を確認できます。

銀行・現金等は残高を表示します。カードは負の差引額を「差引未払額」、0円以上を「差引預り額」と表示します。登録した利用と支払いの差であり、カード会社の確定請求額ではありません。支出入力ではカードを先に表示し、収入と振替では銀行・現金・その他をカードより先に表示します。種類ごとの選択欄でもActualの同じ口座IDを使います。入力途中の「支払元・口座を追加」も同じ種類選択を使い、追加後は元の入力と選択を保持します。

通常は履歴を残す「利用終了」を使います。利用終了した口座は新規登録の選択肢から外れ、「利用を再開する」で戻せます。Actualの `closeAccount` は未使用口座を削除するため、未使用口座では `updateAccount` で状態だけを更新します。取引がある残高0円の口座には `closeAccount` を使います。残高がある場合は利用終了を中止し、先に残高を0円にするよう案内します。残高移動の入力は後続のIssue #74で扱います。

完全削除は取引行が0件かつ残高0円の場合に限定します。削除する意思のチェックと確認ダイアログを要求します。取引や残高がある口座は削除しません。操作直前にも家計簿エンジン側の状態を読み直して条件を検証します。

## 入力途中の記録と分類設定

削除・非表示になったカテゴリ、削除・利用終了した支払元を参照する入力途中のレシートは、既存の店名・日付・金額を保ち、選択肢を空にして再選択を案内します。未処理のレシートで利用できない選択肢を検出した場合は、登録処理中の状態へ進む前に拒否するため、選び直して登録できます。

すでに登録結果の確認中になっている記録では、二重登録を避けるために内容変更の制限を保ちます。元のカテゴリを再表示する、または元の口座を再開して同じ内容で再試行します。登録済みの取引と関連レシートはマスタ管理で削除しません。

店舗の分類設定が削除・非表示になった独自カテゴリを指している場合、次のカテゴリ提案時に無効な設定を削除し、手動で選び直せる状態にします。この再選択のためにAIを呼び出しません。AI提案用の基本カテゴリ語彙は、独自カテゴリの作成を制限しません。

名前・状態等のマスタ情報はActual Budgetの端末内データに保存します。口座の種類はKakeiMatchの端末内記録に保存し、家計簿IDと口座IDに紐付けます。Cloud accountや外部APIへの送信はありません。`.kmb` のActual ZIPに含まれるため、名前変更、収入カテゴリ、利用終了状態はバックアップと復元で維持されます。口座の種類は `.kmb` の端末内記録に含み、復元先の新しい家計簿IDに紐付け直します。口座の種類を含まない既存バックアップも復元でき、その口座は「その他 / 未分類」として表示します。
