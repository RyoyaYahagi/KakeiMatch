# 明細照合の合成評価とノイズ感度

## 読み方と範囲

この評価は、`eval/run-reconciliation-property.ts` の生成モデルが作る合成データに対する結果です。実データとの分布の答え合わせはしていないため、実環境の誤り率や性能の絶対値として公称できません。現時点では、同じ生成モデル上で条件を変えた相対比較に使います。実データで同じ分布が確認できるまでは、この留保を外しません。

今回の測定では照合エンジンを変更していません。ルール版数は `1.2.5` です。生成器の感度分析版は `generatorVersion: 2` です。

## 結果ファイルと再現方法

設定・seedごとの集計、各ケースの判定記録、違反記録、固定ゲートの結果は [感度分析結果JSON](../eval/results/reconciliation-property-sensitivity-v2.json.gz) にあります。JSONとして読む場合は、次のように展開します。

```sh
gzip -dc eval/results/reconciliation-property-sensitivity-v2.json.gz | jq .
```

測定時と同じ実行系を使う場合は、評価コードのコミット `397d7f31acad2fd3c7fc21c8e95ac208c7b94716` をチェックアウトし、依存関係を復元して実行します。

```sh
pnpm install --frozen-lockfile
pnpm eval:reconciliation-property:sensitivity | gzip -9 > eval/results/reconciliation-property-sensitivity-v2.json.gz
```

記録には生成器の版、ルール版、評価コードのコミット、Node／pnpm版、実行コマンド、PRNG、ケースseedの式、各設定・seedのパラメータ、ケース数、指標の分子・分母、固定ゲートの実行回数が入っています。測定基準のソースSHAは `fa5095cb4ccd7fbee0fa9ed98b7496a19cb349f8` です。JSON内の `resultsCommitSHA` は測定結果を最初に記録したコミット `908ad1601b2c60fe3084e96b9718625240d490ca` を示します。再実行時には、発行前のためこの欄は `null` になります。

基準パラメータは、通常日付ずれの最大値2日、確認用日付ずれ `3-7`、低類似度店名の選択率0%、Twinケース率10%です。各ケースは1,200件です。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 直前の旧基準 | v1 | 376 | 28,050 | 24,080 | 23,436 | 0 | 644 | 1.0000 | 0.8355 | 0.9733 |
| 現行評価の基準 | v2 | 376 | 27,916 | 24,016 | 23,371 | 0 | 645 | 1.0000 | 0.8372 | 0.9731 |

旧基準は今回の比較用に、現行mainのルール版 `1.2.5` と旧生成器v1で測り直した値です。これはPR #377に記録されたルール版 `1.2.0` の履歴値とは別です。PR #377のprecision 1.0・Recall@3 1.0を、この表のv1またはv2の測定値として扱いません。

`autoMatchPrecision` は識別可能な自動一致のうち正しいものの割合で、`autoMatchPrecisionAll` は識別不能な自動一致も全て分母に含めます。現行評価v2のseed `376, 1376, 2376, 3376, 4376` では、明確な誤自動一致は全て0、識別不能な自動一致は595〜673件、`autoMatchPrecision` は全て1.0000、適格正解ペアRecall@3は全て1.0000でした。`autoMatchPrecisionAll` は0.9720〜0.9752、自動一致coverageは0.8372〜0.8398でした。識別不能な一致は正しいと実証されたものではなく、全自動一致precisionに反映しています。

## 感度分析の設計と実行量

単因子と基準値を含む粗走査は55設定です。設定値は次のとおりです。

| 因子 | 粗走査の水準 | 基準値 |
| --- | --- | --- |
| 通常の日付ずれ最大日数 | 0, 1, 2, 3, 5, 7, 10, 14, 21, 30日 | 2日 |
| 確認用の日付ずれ | 無効、±1–2、±3–7、±5–10、±8–14、±15–21、±22–30日 | ±3–7日 |
| 低類似度店名を選ぶ率 | 0, 5, 10, 20, 40, 60, 80, 100% | 0% |
| Twinケース率 | 0, 1, 5, 10, 20, 40, 70, 100% | 10% |

日付ずれは通常ケースの70%を0日とし、残りを符号対称の三角分布で最大日数まで選びます。確認用ずれは指定区間から一様に選び、符号は対称です。Twinケース率はケース家族の構成率で、Twin家族では同額・同店・近接日の競合レシートを加えます。加えて、全正解ペアをTwin化する共同極端設定を設けています。

日付×確認用ずれ、日付×低類似度店名、日付×Twin、確認用ずれ×低類似度店名、確認用ずれ×Twin、低類似度店名×Twinの6組について、それぞれ4つの組合せ設定を追加しました。共同極端設定を含む粗走査の55設定をseed 376で実行し、設計で選んだ41の異なる設定を5 seedで実行しました。合計219設定seed実行、262,800ケースです。seedは `376, 1376, 2376, 3376, 4376` です。

固定ゲートは粗走査全体で一度だけ実行しました。1,700ケース、全9チェック成功、違反0件です。合計実行量は固定ゲートを含め264,500ケースでした。粗走査に保たれる設定から崩れる設定への遷移がなかったため、境界細分化は実行していません。揺れた境界もなく、追加seedは0件です。

## 判定基準

この記録で「観測上維持」とするのは、固定ゲートが成功し、安全性違反がなく、各seedで既知正例precisionと候補窓内の適格正解ペアRecall@3がどちらも評価可能かつ1.0の場合です。安全性違反、固定ゲート失敗、評価可能な指標が1.0未満なら「観測上崩れ」とします。どちらかの必須指標が分母0で評価不能なら、維持にも崩れにも数えず「判定不能」とします。

候補窓（前後7日、金額差 `max(100円, 明細金額の3%)`）外の正解ペアは、候補窓内Recall@3の分母から除外します。窓外件数は日付・金額・両方の理由別に別記し、全正解ペアに対する候補coverageにも含めます。したがって、候補窓外の正常な棄却は安全性違反ではありません。

## 測定結果

seed 376の単因子粗走査では、全55設定で安全性違反・明確な誤自動一致は0件、識別可能な自動一致precisionは1.0、候補窓内Recall@3は1.0でした。4因子の全水準でこの二つの結論は観測上維持され、単因子の走査範囲では崩れませんでした。全正解ペアの候補coverageは日付ずれ最大値10〜30日で低下し、30日では0.8345でした。確認用日付ずれは±5日以上の水準で候補coverageが低下し、±8–14日以降は0.9482でした。低類似度店名率とTwin率は候補coverageを下げず、候補窓内Recall@3を維持しました。

全正解ペアに対する自動一致coverageは、単因子のseed 376で次の範囲でした。これは自動化率の変化であり、安全性や候補内Recallの失敗とは分けて読みます。

| 変更因子 | 掃引範囲 | 自動一致coverageの観測範囲 | 主な観測 |
| --- | --- | ---: | --- |
| 通常日付ずれ最大値 | 0〜30日 | 0.6219〜0.8373 | 日付ずれを広げると、自動一致coverageと候補coverageが低下 |
| 確認用日付ずれ | 無効〜±22–30日 | 0.8372〜0.8650 | ±5日以上で候補coverageが低下 |
| 低類似度店名率 | 0〜100% | 0.7117〜0.8372 | 自動化率は低下するが、候補内Recall@3は維持 |
| Twinケース率 | 0〜100% | 0.6728〜0.8596 | 競合が増えるほど自動化率は低下 |

全219設定seedのうち、214設定seedは観測上維持、5設定seedは判定不能で、観測上崩れた設定seedはありませんでした。41の異なる設定を5 seedで確認し、残る14設定は粗走査のseed 376で測定しました。24の相互作用設定（6因子ペア×4セル）は全て5 seedで観測上維持され、明確な誤自動一致を生む組合せ固有の相互作用はありませんでした。自動一致coverageの差の差は最大絶対値0.0199で、組合せによる自動化率の増減として結果JSONに記録しています。

共同極端設定（日付最大30日、確認用±22–30日、低類似度店名100%、Twin率100%、全正解ペアをTwin化）は5 seed全て判定不能でした。自動一致が0件となり、precisionの分母が0になったためです。seed 376では候補窓内Recall@3は1.0ですが、全正解ペアの候補coverageは0.8179、自動一致coverageは0でした。これは誤自動一致の発生ではなく、自動化が停止する極端条件です。判定不能を「維持」と読み替えません。

評価不能の詳細は次のとおりです。

- Twin率0%では、曖昧ペアがないため `ambiguousAbstentionRate` が評価不能です。
- Twin率100%では、回復不能ペアがないため `unrecoverableAbstentionRate` が評価不能です。
- 共同極端設定では自動一致が0件のため `autoMatchPrecision` と `autoMatchPrecisionAll` が評価不能です。回復不能ペアもないため `unrecoverableAbstentionRate` も評価不能です。

全自動一致precision、各種棄却率などは、それぞれの分母が0のとき個別に `not_estimable` として記録しています。必須のprecisionまたはRecall@3が評価不能なseedは、結論判定から外して判定不能として残します。

## 解釈上の留保

この結果から言えるのは、この生成器・この有限個のseed・この測定範囲で、明確な誤自動一致が観測されず、識別不能な自動一致を含む全自動一致precisionが0.9720以上で、候補窓内Recall@3が維持されたことまでです。誤自動一致率が実環境で0であることや、母集団の誤り率を保証するものではありません。実データとの分布の照合と十分な確定履歴が得られるまでは、合成指標は生成モデル内の値として扱い、絶対値の公称や数値保証には使いません。較正の再挑戦とconformal prediction等の数値保証は、この測定の範囲外です。
