# 暗号化クラウド保存の共通形式

Issue #38 段階Aのうち、端末側の暗号化と復旧コードを実装する。同期の版制御は #143（サーバー側の制御は[端末間同期](DEVICE_SYNC.md)）、バックアップ単独利用は後続PRで扱う。このPRではネットワークへ送信せず、現在の `.kmb` 書き出しも変更しない。

## データ境界

通常の端末内利用にはCloud accountを要求しない。将来のクラウド保存では、利用者が明示的に有効化した場合に限り、端末で暗号化したデータと保護済み家計簿鍵を非公開保存先へ送る。平文家計データ、復旧コード、復号鍵は送らない。保存先には暗号文の長さ、識別用UUID、世代・版のつながりが見える。店名、金額、ファイル種別は暗号化する。

この例外は設計条件であり、アップロードの実装や有効化を意味しない。復旧コードは256 bitの無作為値で、端末外へ利用者自身が保存する。PasskeyやCloud accountの回復では復号鍵を再生成できない。全端末と復旧コードを失うと復号できない。

## API

実装は `src/lib/encrypted-household-format.ts`。

| 関数 | 役割 |
| --- | --- |
| `createHouseholdEncryptionKey(householdId, generation)` | 家計簿鍵、復旧コード、保護済み鍵を生成する |
| `recoverHouseholdEncryptionKey(protectedKey, code, expected)` | 元端末に依存せず、家計簿・世代を照合して復旧する |
| `encryptHouseholdBlob(blob, key, context)` | `.kmb` などのBlobを4 MiBずつ暗号化する |
| `decryptHouseholdBlob(blob, key, expectedContext)` | 全チャンク検証後にだけ平文Blobを返す |

家計簿鍵はWeb Cryptoの非抽出 `CryptoKey`（HKDF）を返す。現段階は端末への鍵保存やUIを実装しない。後続実装は鍵をIndexedDBへ保存する場合でも、復旧コードを通常のLocalStorage・バックアップ・ログへ保存しない。

呼出し側は家計簿ID、世代、版ID、親版IDを決定し、既知の期待値を復号へ渡す。暗号文のヘッダーをそのまま期待値に使わない。版公開・最新性・競合・端末資格をこのモジュールでは判断しない。認証付き暗号化だけでは古い正しい版の再送を検出できないため、#143の世代・版制御が必要。

## 形式バージョン1

先頭8 bytesは `KMENC001`、次の4 bytesはbig-endianのJSONヘッダー長。ヘッダーは8 KiB以下で、形式バージョン、家計簿・世代・版・親版、256 bitのsalt、チャンク数、暗号化済み目録長を含む。未知のフィールド・形式は拒否する。

暗号化のたびに新しいsaltを生成し、家計簿鍵からHKDF-SHA-256で版専用のAES-256-GCM鍵を導出する。導出用途とcontextをinfoに含め、復旧用鍵との用途を分離する。同じ版の再試行にもsaltを作り直す。乱数の衝突確率をゼロとは扱わず、暗号学的乱数を使うことを前提とする。

目録のIVは96 bitのゼロ、チャンクは末尾32 bitをbig-endianの1始まりカウンターとする。このカウンターは同じ版専用鍵で一度だけ使う。目録と各チャンクの追加認証データにヘッダー全体と順番を含め、128 bitの認証タグを使用する。空ファイルでも1チャンクを作る。

暗号化済み目録には平文の全長、ファイル種別、各チャンク長を含む。平文は256 MiB、チャンクは最大64個。復号ではヘッダー・期待context・目録・チャンク数/長さ・全ファイル長を検証し、各チャンクの認証に成功してからBlobを返す。途中の平文をコールバックやストレージへ渡さない。全ファイルの `arrayBuffer()` は呼ばず、読み取りは最大4 MiBと目録に分割する。結果Blob全体のメモリー使用量まで4 MiBに制限するものではない。

## 復旧と鍵の切り替え

復旧コードは `KM1-` と8桁hexの8グループ。256 bitの無作為値をHKDFへ入れ、独立のsaltと家計簿・世代・用途からAES-GCM鍵を導出する。保護済み鍵は暗号化した32 bytesの家計簿鍵と16 bytesのタグを持つ。鍵生成・復旧で扱う平文の一時byte配列は処理後にゼロ化する。ただしJavaScript実行環境全体で秘密の完全消去を保証するものではない。

鍵のある端末が残っている場合、新しい世代と鍵・復旧コードを生成し、旧鍵で復号して新鍵で再暗号化できる。本人確認、旧端末資格の失効、古い世代の送信拒否、原子的な公開は #143 の責任で、現段階には含めない。すでに端末へ渡した平文・鍵を遠隔で消せるとは扱わない。

復号に成功したBlobでも `.kmb` のschema検証は別途必要。後続の復元UIは既存 `readPortableBackup` と一時復元経路を利用し、元データを直接上書きしない。#58のActual孤児データ制約も残る。

## 検証と未実装

合成データで、新端末相当の復旧、空/チャンク境界、同じ版の再暗号化、誤ったコード・鍵、別家計簿・世代・版・親版、目録改ざん、末尾改ざん、欠落、並べ替え、別暗号文のチャンク差し替え、余分な末尾データ、鍵の世代切り替えを検証する。これはブラウザー固有の鍵永続化・iPhone実機・R2・同期・同意UIの確認には代わらない。

Chromiumでも独立したブラウザーcontextで、元端末の鍵を渡さない復旧、非抽出鍵のstructured clone、4 MiB境界、改ざん拒否を検証する。`pnpm --dir apps/pwa test:encryption-e2e` をCIに含める。

Web CryptoのAES-GCM、HKDF、非抽出鍵の仕様は[W3C Web Cryptography (2025/04), AES-GCM/HKDF/CryptoKey](https://www.w3.org/TR/webcrypto/)を参照する。暗号形式と運用全体への外部監査は未実施。
