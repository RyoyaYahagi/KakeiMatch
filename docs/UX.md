# UX

現在の主アプリは `apps/pwa` のPWAです。この文書の画面要件はPWAを基準にします。移行前のNext.js画面はlegacy実装としてIssue #39まで保持します。PWAが保存するデータと実機確認の手順は[ローカル保存フロー](LOCAL_FIRST_FLOW.md)を参照してください。

## 最優先

KakeiMatchの主要利用者には、ITに詳しくない家族を想定します。

「多機能な家計簿を使わせる」のではなく、日常的に必要な操作を少ない判断で終えられることを優先します。

## UX原則

### スマートフォンファースト

主要操作はスマートフォンだけで完結できることを前提にします。

- タップ対象を十分大きくする
- 重要操作を届きやすい位置へ置く
- 横スクロールを基本的に使わない
- 表ではなくモバイル向けリストを優先する
- カメラ起動・写真選択を最短導線にする

### 正常なものを見せすぎない

明細照合では「一致した100件」を一件ずつ確認させません。

基本表示は以下を優先します。

- 要確認
- 記録なし
- 処理に失敗したもの

一致済みの詳細は必要な場合だけ開けるようにします。

### AIを意識させない

「Gemini」「Jev」などの技術名を通常ユーザーUIへ露出しません。

ユーザーに必要なのは、

- 読み取りました
- 確認してください
- 登録しました
- 一致しました

という結果です。

### 自動処理の理由を確認できる

確認画面では最低限、

- レシート
- カード明細
- 金額
- 日付
- 店舗
- なぜ候補になったか

を比較できるようにします。

### 自分のデータだけを扱う

各ユーザーはログイン後、自分の支出・レシート・明細・照合結果だけを見ます。

家族一覧や他ユーザーの支出はMVPの通常UIに出しません。

## MVPの主要画面

### ログイン

PWAの家計簿、レシート手入力、PayPay明細import、照合はCloud accountへログインせずに利用できます。AI抽出とカテゴリ提案にはCloud accountのPasskey sessionが必要です。移行前Next.jsアプリのログイン画面はlegacy機能です。

AI利用からログアウトしても、端末内の家計データは削除しません。

### ホーム

最も頻繁に使う画面です。

拡張後の配置は「機能拡張後の情報設計」に従います。以下はレシート中心の初期構成です。

初期構成の優先順位:

1. レシートを登録
2. 要確認件数
3. 今月の支出
4. 最近の支出

概念例:

```text
今月の支出
¥82,430

[ レシートを登録 ]

要確認  2件 >

最近の支出
ベイシア      ¥3,284
ガスト        ¥1,280
JR東日本      ¥1,980
```

ダッシュボード化しすぎず、日常操作を優先します。

### レシート登録

第一目標は撮影から保存までの操作数を減らすことです。

画像を選ぶと、PWAは先にレシート原本を端末内へ保存します。画像からの読み取りはユーザーが「AIで読み取る」を選んだ時だけ行います。手入力も選べます。画像は10 MiBまで端末に保存します。AI Gatewayが受け付ける上限は6 MiBなので、それを超える画像は保存だけ行い、AI送信を始めません。

```text
撮影 / 写真選択 / 手入力
  ↓
端末へ保存
  ↓
希望時にAIで読み取り・カテゴリ提案
  ↓
店名・金額・日付・カテゴリ・支払元を確認
  ↓
Actual Budgetへ登録
```

初期MVPでは誤登録の影響を確認するため、重要項目の確認を残して構いません。運用データが溜まった後に確認省略を検討します。

日常的に修正させる項目は最小限にします。

- 店名
- 日付
- 金額
- カテゴリ

商品明細の細かな修正を日常操作として強制しません。

### 支出一覧

一行をコンパクトに表示します。

```text
9/28  ベイシア          ¥3,284
9/27  ガスト            ¥1,280
9/27  JR東日本          ¥1,980
```

押すと詳細を開きます。

常にCardを多用して画面を縦に伸ばさないでください。

### 支出詳細

必要な情報だけを段階的に表示します。

- 店名
- 金額
- 日付
- カテゴリ
- 決済手段（取得できる場合）
- 照合状態
- レシート画像
- 編集

### 明細インポート

基本フロー:

1. 決済サービスを選ぶ
2. ファイルを選ぶ
3. 読み込み結果を見る

読み込み後は「照合」画面で結果を更新できます。

現在のPWAはPayPayの限定された公式CSV形式を受け付けます。三井住友カード、楽天カード、イオンカードは明細行の意味を安全に確定できていないため、選択・推測して取り込まず、拒否します。

CSVの解析、原本保存、canonical行の保存は端末内で完了し、CloudflareやAI providerへファイルを送信しません。

### 照合結果

最上部に結果を集約します。

```text
明細 82件

✓ 自動確認済み  76
△ 要確認         4
! 記録なし       2
```

デフォルトでは「要確認」「記録なし」を先に見せます。
Actualへの反映に失敗した判断はさらに上へ表示します。自動一致は件数を中心に示し、個別の確認操作を求めません。レシートに対応する明細がまだない場合は「明細待ち」の件数だけを補助表示します。

### 要確認詳細

スマートフォンでは左右比較ではなく、縦方向に比較します。

```text
カード明細
ベイシア
9/29
¥3,284

一致候補
レシートあり
ベイシア
9/28
¥3,234

日付差: 1日
金額差: ¥50

[同じ支出として処理]
[別の支出]
```

「不正取引」という強い表現は使わず、「記録が見つかりません」「確認してください」とします。
「別の支出」は表示中のレシート候補だけを除外し、残りの候補を続けて示します。候補がなくなった明細ではカテゴリと支払元を選んで家計簿へ登録できます。返金には支出登録の操作を表示しません。古い照合結果からの操作は拒否し、画面更新を促します。家計簿への反映が失敗した場合は判断を残し、「もう一度試す」を表示します。

自動確認済みの明細は「自動確認済みの内容を見る」を開くと確認できます。通常は折りたたみ、要確認の明細を中心に表示します。各行を開くと明細と対応レシートの日付・時刻・店名・金額を比較でき、登録済みレシートの確認画面にも移動できます。照合を更新した後も、保存済みの自動確認結果を表示します。

## 機能拡張後の情報設計

Issue #65〜#79で家計簿機能を増やしても、機能ごとに画面・Card・主要CTAを追加しません。
日常利用は **概要を確認し、詳細を開き、必要な場合に編集する** 順序を基本とします。ホームには概要を置き、詳細機能は遷移先へ置きます。
この節はIssue #80で定める拡張後の設計です。現行PWAの画面をすべて変更済みという意味ではありません。Issue #65〜#79の各実装では、この節と下記のモバイル画面構成を参照します。

### 主要ナビゲーション

主要ナビは原則4つ以内にします。

- ホーム
- 記録
- 照合
- 設定

従来の「支出」は、収入・振替も含むため「記録」へ広げます。
口座、予算、検索、定期登録等の追加だけを理由に下部ナビを増やしません。

### ホーム

ホームは「今月どうなっているか」と「次に何をするか」を短時間で把握する画面です。
ダッシュボード化しすぎず、詳細を常時展開しません。

優先して表示する内容:

1. 選択月と月切替
2. 収入 / 支出 / 収支
3. Primary CTA「＋記録」
4. 要確認件数
5. 予算の概要
6. 支出カテゴリ構成の概要
7. 最近の記録

予算カテゴリ全件、口座全件、詳細検索条件、定期登録一覧はホームへ直接並べません。
概要をタップして詳細へ進みます。

### ＋記録

ホームへ複数の登録ボタンを並べず、Primary CTAは原則「＋記録」1つに集約します。

「＋記録」では支出・収入・口座間振替を選びます。支出を選んだ場合だけ、手入力とレシート入力を選ぶ画面を挟みます。

新規入力の戻る操作は直前の選択画面へ戻します。支出手入力とレシート入力は支出方法の選択へ、収入と振替は「記録する」へ戻ります。支出方法の選択からは「記録する」へ戻り、「記録する」からは記録一覧へ戻ります。編集のキャンセルと保存後は元の記録詳細へ戻し、検索から開いた詳細では検索結果へ戻れる状態を保ちます。

### 記録

収入・支出・振替を同じ時系列で確認できる画面です。
一覧はコンパクトな1行表示を基本にし、詳細情報は行をタップして開きます。

この領域に以下を集約します。

- 月内の取引一覧
- 検索 / フィルタ
- 取引詳細
- 取引の編集 / 削除
- 口座一覧への導線（残高確認は記録画面からも可能。口座の追加・変更は設定で行う）

レシート由来の取引詳細では必要に応じて、レシート画像、品目、品目価格、品目カテゴリ、値引き等を段階的に表示します。

### 予算

ホームでは「使用額 / 予算額」等の概要だけを表示します。
タップ後の予算詳細でカテゴリ別の予算額、使用額、残額、使用率を確認します。
高度なEnvelope budgeting UIは通常画面へ持ち込みません。

### 設定

日常的に触らない管理機能は設定へ集約します。

- カテゴリ
- 支払元・口座
- 定期登録
- 予算設定
- 明細インポート
- バックアップ / 端末データ
- AIアカウント

設定トップは管理画面への入口を1行ずつ表示します。各行をタップすると管理画面へ進みます。

### AI / Rules

Gemini、Jev、Actual、Rules、confidence等の内部実装を通常UIへ露出しません。

カテゴリ学習やRule適用は原則バックグラウンドで行い、ユーザーに必要な場合だけ「いつもの分類」等の短い説明を表示します。
Ruleで分類できる場合はAIを使わず、Ruleで決まらないものだけAIへフォールバックしますが、この処理順自体を日常画面で説明しません。

### 機能追加時の配置ルール

- 1画面のPrimary CTAは原則1つ
- 機能ごとにCardを追加しない
- 一覧はコンパクトな1行表示とし、タップ後に詳細を開く
- 概要画面に全詳細を置かない
- 管理機能は設定へ寄せる
- 機能追加だけを理由に主要ナビを増やさない
- 個別IssueのUIがこの構造と衝突する場合は、画面側で例外を増やす前にUX文書を更新する

## ナビゲーション

拡張後の主要ナビは「ホーム / 記録 / 照合 / 設定」の4つ以内とします。
レシート入力は「＋記録」から、明細インポートは設定から開始します。
未実装の機能への入口は表示しません。各機能を追加するIssueで既存の入口を移し、同じ機能への主要な入口を重複させません。

## 拡張後のモバイル画面構成

以下は幅375 CSS pxのスマートフォンを想定したワイヤーフレーム（配置と遷移を示す設計図）です。
表示する金額、店名、件数はすべて架空の例です。各画面の内容は縦に並べ、横スクロールを必要としません。
「>」は詳細画面への入口、「[ ]」は操作を表します。

### ホームと記録追加

ホームでは収支と要確認件数を上部へ置きます。予算とカテゴリの概要を押すと詳細へ進みます。
「＋記録」を押すと選択画面を開きます。選択画面の4項目は同じ強さの行として表示し、4つの主要ボタンにはしません。

```text
ホーム
[前月] 2026年10月 [翌月]
[当月へ戻る]
収入 ¥250,000
支出 ¥82,430
収支 +¥167,570
[＋記録]                 ← 主要操作
△ 要確認 2件             > 照合
予算 ¥82,430 / ¥120,000   > 予算詳細
支出カテゴリの小さな円グラフ
食費 ¥30,000（36%）ほか   > カテゴリ内訳
最近の記録
10/1 スーパー例  −¥3,284 > 記録詳細
[ホーム] [記録] [照合] [設定]
```

```text
記録追加
[戻る]
支出             > 支出方法選択
収入             > 収入入力
口座間振替       > 振替入力
```

```text
支出を記録
[戻る]
手入力           > 支出入力
レシートから入力 > 撮影 / 写真選択
```

入力画面では必要な項目と主要操作「登録する」だけを表示します。
入力中に戻る・キャンセルを選んでも入力を不必要に失わないようにします。破棄する場合は入力が消えることを伝えます。

### 記録一覧・詳細・編集

一覧は日付・店名または内容・金額を1行にまとめます。収入は「＋」、支出は「−」、振替は「振替」と明示します。
検索条件は検索を開いてから表示します。品目や画像は詳細で開き、一覧を縦に伸ばしません。

```text
記録
[前月] 2026年10月 [翌月]
[検索] [絞り込み]
口座・残高を見る        > 口座と残高（管理は設定から）
10/1 給与       +¥250,000 > 記録詳細
10/1 スーパー例   −¥3,284 > 記録詳細
10/1 現金→銀行       振替 > 記録詳細
[ホーム] [記録] [照合] [設定]
```

```text
記録詳細
[記録へ戻る]
スーパー例  支出 ¥3,284
2026/10/1  食費  現金
✓ 照合済み
レシート画像 > 開く
品目         > 開く
[編集する]               ← 主要操作
[削除する]               ← 補助的な削除操作
```

編集画面は詳細から開き、主要操作を「変更を保存」にします。振替では移動元・移動先を表示し、収入・支出とは区別します。
削除は確認後に実行し、削除直後の取り消しを用意します。具体的な挙動はIssue #75で実装します。

### 照合と設定

照合は要確認・記録なしを中心にし、正常な一致は折りたたみます。比較は縦に表示します。
設定は管理画面への入口だけを表示し、カテゴリや口座の全件を展開しません。

```text
照合
△ 要確認 2件 / ! 記録なし 1件
[照合を更新]             ← 主要操作
△ スーパー例 ¥3,284      > 比較・判断
! 店舗例 ¥1,000           > 詳細
✓ 自動確認済み 76件       > 開いて確認
[ホーム] [記録] [照合] [設定]
```

```text
設定
カテゴリ                 > 収入 / 支出の管理
支払元・口座             > 口座の管理
定期登録                 > 一覧・詳細・編集
予算設定                 > 月別カテゴリ予算
明細インポート           > ファイル選択
バックアップ / 端末データ > 保存・復元・整理
AIアカウント             > 本人確認・利用枠
[ホーム] [記録] [照合] [設定]
```

## 設定: バックアップと端末データ

設定画面では、最後にバックアップファイルを生成した日時、ブラウザーの保存量の目安、保存維持の状態を示します。生成日時はFilesなどへの保存完了ではないことを説明し、`.kmb`を端末外へ保存するよう案内します。ファイルは暗号化されていないため、他人へ渡さないよう伝えます。[端末内データのバックアップと復元](LOCAL_BACKUP.md)

復元では現在の家計データと合併せず、新しい保存先へ読み込んでから切り替えます。復元前のデータへ戻る操作を用意します。画像・CSV原本の削除は、削除件数と保存容量を表示し、削除後に原本を確認できなくなることを明示してから実行します。原本削除では確認値、明細行、照合結果、判断記録を消しません。[実装: `local-backup-ui.ts`](../apps/pwa/src/local-backup-ui.ts) [実装: `local-data-lifecycle.ts`](../apps/pwa/src/local-data-lifecycle.ts)

端末内家計データの全消去には確認と「すべて削除」の入力を求めます。Cloud account、Passkey、契約、AI利用権限には影響しないと説明します。復元中にActual metadataを読み込めない孤児budgetが検出された場合は、アプリからの全消去を停止し、元データのバックアップ後にブラウザーのサイトデータを削除するよう案内します。この削除は同じoriginの他のブラウザーデータやログイン状態にも影響することがあります。[端末内データのバックアップと復元](LOCAL_BACKUP.md)

## エラーUX

「エラーが発生しました」だけにしません。

- レシートから金額を読み取れませんでした → 金額入力へ
- 明細形式を認識できませんでした → 対応サービスとファイル例を表示
- Actual Budgetに接続できません → 入力を失わず再試行可能にする
- Geminiが利用できません → 画像を保持し、後で再解析可能にする
- Jev分類に失敗しました → カテゴリを未分類としてユーザーが選べるようにする
- Cloud accountからログアウトしました → 端末内の家計データはそのまま使えることを伝える
- AIの月間利用枠に達しました → 画像を端末に残し、手入力へ進める
