# UX

## 最優先

KakeiMatchの主要利用者には、ITに詳しくない家族を想定します。

「多機能な家計簿を使わせる」のではなく、日常的に必要な操作を少ない判断で終えられることを優先します。

## UX原則

### スマートフォンファースト

主要操作はスマートフォンだけで完結できることを前提にします。

- タップ対象を十分大きくする
- 重要操作を届きやすい位置へ置く
- 横スクロールを基本的に使わない
- 表ではなくモバイル向けリストを優先する
- カメラ起動・写真選択を最短導線にする

### 正常なものを見せすぎない

明細照合では「一致した100件」を一件ずつ確認させません。

基本表示は以下を優先します。

- 要確認
- 記録なし
- 処理に失敗したもの

一致済みの詳細は必要な場合だけ開けるようにします。

### AIを意識させない

「Gemini」「Jev」などの技術名を通常ユーザーUIへ露出しません。

ユーザーに必要なのは、

- 読み取りました
- 確認してください
- 登録しました
- 一致しました

という結果です。

### 自動処理の理由を確認できる

確認画面では最低限、

- レシート
- カード明細
- 金額
- 日付
- 店舗
- なぜ候補になったか

を比較できるようにします。

### 自分のデータだけを扱う

各ユーザーはログイン後、自分の支出・レシート・明細・照合結果だけを見ます。

家族一覧や他ユーザーの支出はMVPの通常UIに出しません。

## MVPの主要画面

### ログイン

目的は、家族それぞれが自分の家計簿へ簡単かつ安全に入ることです。

MVPでは複雑なSSOを必須にしません。ただし、インターネット公開時に認証なしにはしません。

### ホーム

最も頻繁に使う画面です。

優先順位:

1. レシートを登録
2. 要確認件数
3. 今月の支出
4. 最近の支出

概念例:

```text
今月の支出
¥82,430

[ レシートを登録 ]

要確認  2件 >

最近の支出
ベイシア      ¥3,284
ガスト        ¥1,280
JR東日本      ¥1,980
```

ダッシュボード化しすぎず、日常操作を優先します。

### レシート登録

第一目標は撮影から保存までの操作数を減らすことです。

```text
撮影 / 写真選択
  ↓
解析中
  ↓
店名・金額・日付・カテゴリ
  ↓
高信頼 → 最小確認
低信頼 → 修正
  ↓
登録
```

初期MVPでは誤登録の影響を確認するため、重要項目の確認を残して構いません。運用データが溜まった後に確認省略を検討します。

日常的に修正させる項目は最小限にします。

- 店名
- 日付
- 金額
- カテゴリ

商品明細の細かな修正を日常操作として強制しません。

### 支出一覧

一行をコンパクトに表示します。

```text
9/28  ベイシア          ¥3,284
9/27  ガスト            ¥1,280
9/27  JR東日本          ¥1,980
```

押すと詳細を開きます。

常にCardを多用して画面を縦に伸ばさないでください。

### 支出詳細

必要な情報だけを段階的に表示します。

- 店名
- 金額
- 日付
- カテゴリ
- 決済手段（取得できる場合）
- 照合状態
- レシート画像
- 編集

### 明細インポート

基本フロー:

1. 決済サービスを選ぶ
2. ファイルを選ぶ
3. 読み込み結果を見る

照合は後続のIssueで実装します。

対象:

- 三井住友カード
- 楽天カード
- イオンカード
- PayPay

providerは利用者が明示的に選択します。CSVから自動判定しません。三井住友カード・楽天カード・イオンカードは現在のCSV列名が未確認のため、選択されても安全に取り込みを拒否します。

### 照合結果

最上部に結果を集約します。

```text
明細 82件

✓ 自動確認済み  76
△ 要確認         4
! 記録なし       2
```

デフォルトでは「要確認」「記録なし」を先に見せます。

### 要確認詳細

スマートフォンでは左右比較ではなく、縦方向に比較します。

```text
カード明細
ベイシア
9/29
¥3,284

一致候補
レシートあり
ベイシア
9/28
¥3,234

日付差: 1日
金額差: ¥50

[同じ支出として処理]
[別の支出]
```

「不正取引」という強い表現は使わず、「記録が見つかりません」「確認してください」とします。

## Navigation

MVPでは主要ナビゲーションを増やしすぎません。

候補:

- ホーム
- 支出
- 照合
- 設定

レシート登録は主要CTAとしてホームから直接開始できるようにします。

## エラーUX

「エラーが発生しました」だけにしません。

- レシートから金額を読み取れませんでした → 金額入力へ
- 明細形式を認識できませんでした → 対応サービスとファイル例を表示
- Actual Budgetに接続できません → 入力を失わず再試行可能にする
- Geminiが利用できません → 画像を保持し、後で再解析可能にする
- Jev分類に失敗しました → カテゴリを未分類としてユーザーが選べるようにする

## アクセシビリティ

最低限:

- 本文16px相当以上を基準
- 色だけで状態を区別しない
- 十分なコントラスト
- タップ領域44px程度以上を目安
- focus stateを消さない
- form labelを明示
- 読み上げ可能なボタン名
- 成功/警告/エラーをアイコン・文言でも区別

## 実装前のUI確認

主要画面についてモバイル幅のワイヤーフレームを作り、以下を確認します。

- レシート登録が迷わず開始できるか
- 要確認件数が埋もれていないか
- 情報密度が高すぎないか
- 1画面に主要CTAが増えすぎていないか
- 専門用語なしで理解できるか
- 戻る操作やキャンセルで入力内容を不必要に失わないか
