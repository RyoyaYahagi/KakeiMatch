# UX

この文書は、本番アプリ `apps/pwa` の画面構成と操作の基準です。見た目の決まりは[デザイン](DESIGN.md)に定めます。保存するデータと実機確認の手順は[ローカル利用フロー](LOCAL_FIRST_FLOW.md)を参照してください。

## 位置づけ

この版は2026年10月のUI刷新で定めた**目標の設計**です。現行の画面はまだ一部しか追いついていません。各画面は「移行状況」の順に、小さなPull Requestで置き換えます。実装と食い違う場合は、この文書を正とします。この文書を変えずに、画面側で例外を増やさないでください。

## 利用者と最優先

主な利用者は、ITに詳しくない家族です。

- 毎日の記録を、迷わず少ない操作で終えられること
- 確認が必要なものだけに気づけること
- 開くたびに「明るく、親しみやすく、読みやすい」と感じられること

機能をたくさん見せるより、次に何をすればよいかが分かることを優先します。

## UX原則

### スマートフォンで完結する

- 主な操作は親指が届く画面の下半分に置く。ナビは画面下に固定する
- タップできる場所は44 CSS px以上にする
- 横スクロールを使わない。表ではなく1行のリストを使う
- 撮影・写真選択までの操作を最短にする

### 正常なものを見せすぎない

明細照合では、自動で一致した取引を一件ずつ確認させません。件数で示し、必要な時だけ開けるようにします。先に見せるのは次の3つです。

1. 反映に失敗したもの
2. 要確認
3. 記録なし

### 技術を意識させない

Gemini、Jev、Actual、Rules、confidence等の内部名を通常の画面に出しません。利用者に伝えるのは結果です。

- 読み取りました
- 確認してください
- 登録しました
- 一致しました

写真からの読み取りとカテゴリ提案は、補助として「AIで読み取る」と表示して構いません。分類の学習やルールの適用は裏で行い、必要な時だけ「いつもの分類」等の短い説明を添えます。

### 判断の理由を見せる

照合の確認画面では、明細と記録の日付・金額・店名を縦に並べ、どこが違うか、なぜ候補になったかを示します。

### 入力を失わない

戻る、キャンセル、カテゴリや口座の途中追加、オフライン、保存失敗のどの場合も、入力した内容を不必要に失いません。破棄する時は、入力が消えることを伝えて確認します。

### 状態を色だけで伝えない

一致・要確認・記録なし・失敗は、必ず記号と文言を色に添えます。

| 状態 | 記号 | 文言の例 | 色の役割 |
| --- | --- | --- | --- |
| 一致 | ✓ | 自動で一致 / 照合済み | success |
| 要確認 | △ | 金額が¥50違います | warning |
| 記録なし | ! | 記録が見つかりません | danger |
| 失敗 | ! | 反映できませんでした | danger |

「不正」「不正利用」とは書きません。対応する記録がない理由には、レシートの紛失、オンライン決済、利用日と計上日の差、返品などがあるためです。

### 自分の端末のデータだけを扱う

家計データは利用者の端末に保存します。家族一覧や他の利用者の支出は表示しません。

## 情報設計

### 下部ナビ

画面下に固定し、5つの枠を置きます。移動先は4つです。中央の「＋追加」は移動先ではなく、どの画面からでも記録を始めるための主要操作です。

```text
[ホーム] [記録] [ ＋ 追加 ] [照合] [設定]
```

- 中央の「＋追加」は丸い大きなボタンにして、ナビから少し浮かせる。読み上げ名は「記録を追加」
- 照合タブには、確認が必要な件数（要確認＋記録なし＋反映失敗）をバッジで表示する。読み上げ名にも件数を含める（例：「照合（確認が必要 6件）」）
- 選択中のタブは、色に加えて太字と `aria-current="page"` で示す
- 入力・確認・詳細など1つの作業に集中する画面でも、ナビは表示したままにする。入力は端末に自動で保存されるため、途中で別のタブへ移っても失われない。上部の「戻る」（新規入力では「キャンセル」）と、ナビの上に固定した主要ボタンで操作する
- 口座、予算、検索、定期登録などを理由に、ナビの移動先を増やさない

### 配置ルール

- 1画面の主要ボタンは1つ。ナビがある画面では「＋追加」がそれにあたる
- 一覧は1行表示にし、タップして詳細を開く
- 概要の画面に全部の詳細を置かない。概要からタップして詳細へ進む
- 日常的に触らない管理機能は設定へ寄せる
- まとまりは「セクション」（角の丸い面）で囲う。1件ごとにカードを作らない
- 未実装の機能への入口は表示しない。同じ機能への主要な入口を重複させない

## 画面

以下のワイヤーフレームは幅375〜390 CSS pxのスマートフォンを想定しています。金額・店名・件数はすべて架空の例です。「>」はタップで詳細へ進む行、「[ ]」はボタン、「( )」は選択ボタンまたはカテゴリのアイコンを表します。

### ホーム

「今月どうなっているか」と「次に何をするか」が数秒で分かる画面です。上から次の順に並べます。

```text
[‹]        2026年10月        [›]
┌ 今月の支出 ─────────────────┐
│ ¥82,430                      │
│ [収入 ¥250,000] [収支 +¥167,570] │
│ 10月の予算 · ¥82,430 / ¥120,000   │
│ ■■■■■■■□□□         残り ¥37,570 > │
└──────────────────────────────┘
△ 確認が必要な明細 6件          > 照合
  要確認 4・記録なし 2
┌ 支出の内訳                     ┐
│ (円グラフ)  ● 食費    37%      │
│   食費      ● 日用品  15%      │
│   37%       ● 交通    12%      │
│             ● その他  36%      │
│ ▸ すべてのカテゴリ             │
└──────────────────────────────┘
┌ 最近の記録            すべて > ┐
│ スーパーみどり 10/2・楽天カード −¥3,284 │
│ 給与 10/1・収入・銀行口座   +¥250,000 │
│ 現金 → 銀行口座 10/1・振替    ¥10,000 │
└──────────────────────────────┘
[ホーム] [記録] [＋追加] [照合] [設定]
```

- 当月以外を表示している時は、月の表示の下に「当月へ戻る」を出す
- 今月の支出の数字を画面でいちばん大きくする
- 予算の概要は、支出のセクションの中に進み具合のバーと残り（超過時は「超過 ¥…」）として置く。タップするとその場でカテゴリ別の予算と「この月の予算を変更」を開く。予算が未設定の月は「予算を設定する」と表示する
- 確認が必要な明細が1件以上ある時だけ、警告色の帯を表示する。帯の補足には反映失敗・要確認・記録なしの内訳を書く。0件の時は帯を出さない。明細を一度も取り込んでいない時だけ、照合への案内行「明細を取り込んで自動で照合する」を補助として1つ表示する
- 支出の内訳は円グラフ（ドーナツ型）にする。上位3カテゴリと「その他」の最大4区分にし、凡例に割合を文字で書く。中央には最も多いカテゴリの名前と割合を書く。全カテゴリの金額と割合は「すべてのカテゴリ」を開いて見せる
- 最近の記録は3件まで。続きは「すべて」から記録一覧へ進む

### ＋追加（記録の種類を選ぶ）

「＋追加」を押すと、今の画面の上に、下からせり出すシートを開きます。支出の方法も含めて、1枚のシートで選べるようにします。

```text
何を記録しますか？                    [×]
┌──────────────────────────────┐
│ [カメラ] レシートを撮る            > │ ← 主要
│    写真を残して、内容を読み取れます  │
└──────────────────────────────┘
  保存した写真から                    >
  支出を手入力                        >
  収入                                >
  口座間振替                          >
```

- 「レシートを撮る」だけを主要ボタンの見た目にする。残りの4つは同じ強さの行にする
- 「レシートを撮る」はカメラを起動する。「保存した写真から」は写真の選択を開く
- ×（閉じる）、背景のタップ、Escキー、下へのスワイプ（80 px以上）でシートを閉じる。下の画面はそのまま残る
- シートを開いている間は、後ろの画面を操作できない（モーダル）

### 支出の入力（手入力・レシート共通）

手入力とレシートで同じ画面を使います。上から次の順に並べ、「登録する」は画面下に固定します。

```text
‹ キャンセル
支出を入力
[画像]  [AIで読み取る]               ← レシートの時だけ
金額（円）
┌ 3284 ────────────────────────┐ ← 大きな数字
店名・支払先
[スーパーみどり                    ]
日付
[2026-10-02                       ]
(今日 10/2) (昨日)
支出カテゴリ
[食費✓][日用品][交通][娯楽]
[光熱][通信][医療][すべて表示（9）]
[カテゴリを追加]
支払元
[楽天カード                      ⌄] [支払元・口座を追加]
▸ 時刻・メモを追加（任意）
▸ 購入内容（任意）                   ← 品目・値引き・税額
──────────────────────────────
[            登録する            ]  ← ナビの上に固定
```

- 金額を最初の入力欄にして、数字キーボード（`inputmode="numeric"`）を開く
- 日付は入力欄の下の「今日」「昨日」で選べるようにする。それ以外の日は日付の入力欄で選ぶ
- カテゴリはアイコン付きのボタンを4列で並べ、選んだものに枠と背景色を付ける（読み上げでは単一選択のラジオボタン）。9件以上ある時は7件と「すべて表示」を出し、選んでいるカテゴリは常に表示する。並びは家計簿のカテゴリの順で、利用回数による並べ替えはしない。提案したカテゴリには「いつもの分類」と短く添える
- 品目ごとのカテゴリや、検索・照合のカテゴリは選択欄のまま使う
- 支払元は、支出ではクレジットカードを先に並べる
- 時刻とメモは「時刻・メモを追加（任意）」（手入力の収入・振替では「メモを追加（任意）」）に、品目・値引き・税額は「購入内容（任意）」に畳む。値が入っている時は開いた状態で表示する

日常的に直してもらう項目は、店名・日付・金額・カテゴリに絞ります。品目の細かな修正を日常の操作として求めません。

#### レシートの場合

1. 撮影または写真を選ぶと、まずレシートの原本を端末に保存する
2. 画像のすぐ下に「AIで読み取る」を補助のボタンとして表示する。読み取りは利用者が押した時だけ行う
3. 読み取ったら、上部に「✓ 写真から読み取りました／違うところだけ直してください」と表示し、各欄に値を入れる
4. 読み取り済みの時は「再読み取り」とし、利用枠を使うことと入力が置き換わることを確認してから実行する

画像は10 MiBまで端末に保存します。AIの受け付け上限は6 MiBなので、それを超える画像は保存だけ行い、送信しません。読み取った値と利用者が確定した値は、内部で区別して保存します。

#### 品目と値引き

「時刻・メモ・品目を追加（任意）」を開くと、品目と値引きを入力できます。

- 値引き額は正の数で入力する。加算の調整は種類で選ぶ
- 品目を削除するボタンは、編集欄のカテゴリの下に置く
- 入力欄から離れても、編集欄を自動で閉じない
- 入力した合計金額を、品目の合計で上書きしない

### 収入・口座間の振替の入力

支出と同じ画面構成にし、項目だけを変えます。

- 収入：金額、内容、日付、収入カテゴリ、入金先
- 振替：金額、日付、振替元、振替先。収入や支出とは区別して表示する
- 入金先・振替元・振替先では、銀行口座と現金を先に並べる

### 入力途中でカテゴリ・口座を追加する

カテゴリのボタン群の最後に「＋追加」を、支払元・入金先・振替元・振替先の選択欄に「支払元・口座を追加」を置きます。追加は小さなダイアログで行います。

- 支出からは支出カテゴリ、収入からは収入カテゴリだけを追加する。レシートの品目カテゴリにも同じ導線を使う
- 支払元の追加では、銀行口座・クレジットカード・現金・その他 / 未分類の種類を選べる
- 追加しても「入力へ戻る」を選んでも、元の入力画面へ戻る。日付・金額・店名・メモ・品目の入力を保持する
- 追加した後は一覧を再取得し、新しい項目を選択する。振替の片方から追加した場合は、もう片方の選択を保持する
- 追加には設定画面と同じフォームと保存処理を使う。名称変更、非表示、利用終了、削除は設定で行う

### 記録一覧

収入・支出・振替を同じ時系列で見る画面です。月では区切らず、新しい順に最大100件を表示します。先月の日付で登録した記録も、登録した直後にこの一覧で見つけられるようにするためです。月や期間で絞る時は検索を使います。

```text
記録                                [検索]
[すべて|支出|収入|振替]
口座・残高を見る                      >
┌ 確認待ち 1件                       ┐
│ (レ) 未入力のレシート      確認する │
└──────────────────────────────┘
┌ 10月2日（金）              −¥4,364 ┐
│ (食) スーパーみどり          −¥3,284 │
│      食費・楽天カード・レシート     │
│ (食) カフェこもれび          −¥1,080 │
│      食費・PayPayカード             │
└──────────────────────────────┘
┌ 10月1日（木）            +¥243,180 ┐
│ (収) 給与                  +¥250,000 │
│ (振) 現金 → 銀行口座         ¥10,000 │
└──────────────────────────────┘
```

- 登録前のレシート・支出は「確認待ち」として一覧の先頭にまとめ、「確認する」から入力へ進む
- 日付ごとにまとめ、見出しに曜日とその日の収支（振替を除く）を出す
- 1行の構成：左にカテゴリのアイコン、中央に店名または内容と補足（カテゴリまたは種類・支払元・画像付きのレシートなら「レシート」）、右に金額
- 行の読み上げ名には、見出しで省いた日付も含める（例：「スーパーみどり · 10/2 · 食費 · 楽天カード · −¥3,284」）
- 金額は右揃えにし、等幅の数字で表示する。支出は「−¥」、収入は「+¥」に収入の色、振替は記号なしで補足に「振替」と書く
- 照合で確認が必要な明細の候補になっている記録は、補足の先頭に警告色で「△ 要確認」と示し、読み上げ名にも「要確認」を含める
- 種類の絞り込みは上部の切り替えで行う。店名や金額などの詳しい条件は検索を開いてから表示する
- 「口座・残高を見る」から残高を確認できる。口座の管理は設定で行う

### 記録の詳細・編集・削除

```text
‹ 記録一覧へ戻る
支出の記録
┌──────────────────────────────┐
│ 金額                    ¥3,284 │ ← 大きく表示
│ 日付                2026-10-02 │
│ 店名・支払先     スーパーみどり │
│ カテゴリ                  食費 │
│ 支払元              楽天カード │
│ メモ                      なし │
└──────────────────────────────┘
[          編集する          ]   ← 主要
           削除する              ← 文字だけの破壊的操作
```

- 戻る操作は画面の左上に置く。検索から開いた場合は「検索結果へ戻る」にする
- 振替では振替元口座と振替先口座を表示する
- レシート由来の記録も同じ構成にする。金額・日時・カテゴリと支払元・「✓ 家計簿へ登録済みです。」・メモを1つのまとまりに置き、レシート画像、購入内容（品目・価格・カテゴリ）、値引き・調整はそれぞれ折りたたんで段階的に開く
- 編集画面は詳細から開き、主要ボタンを「変更を保存」にする
- 削除は確認してから行い、削除直後の10秒間は取り消せるようにする。詳細は[取引削除と取り消し](LOCAL_TRANSACTION_DELETION.md)を参照してください

### 照合

```text
照合                         [照合を更新する]
! 家計簿への反映が完了していません [反映を再試行する]  ← 失敗がある時だけ
┌△ 要確認┐┌! 記録なし┐┌✓ 自動で一致┐
│  4件   ││   2件    ││    76件    │
└────────┘└──────────┘└────────────┘
明細待ちの支出 3件（明細を取り込むと照合します）
┌──────────────────────────────┐
│ ⬆ 明細CSVを取り込む          ▸ │  ← 開くとサービスとファイルを選ぶ
└──────────────────────────────┘
┌ 確認してください ─────────────┐
│ △ スーパーみどり        ¥3,284 ▸ │
│   9/29 · 金額が¥50違います        │
│ △ カフェこもれび          ¥880 ▸ │
│   9/26 · 候補が2件あります        │
│ ! オンラインストア      ¥2,980 ▸ │
│   9/18 · 記録が見つかりません     │
└──────────────────────────────┘
▸ 自動で一致した内容を見る（76件）
```

- 上部に件数を3つの枠で並べる。要確認と記録なしは状態の色を背景にし、自動で一致は控えめにする。読み上げ用に「照合の結果：自動で一致 2件 · 要確認 1件 · 記録なし 2件 · 明細待ち 0件」の文を添える
- 反映に失敗した判断は、件数の枠より上に危険色の帯で示す
- 「確認してください」には、要確認、記録なしの順に並べる。各行の補足には、日付と何が違うかを短い文で書く（金額が¥50違います、日付が3日ずれています、候補が2件あります、記録が見つかりません）
- 自動で一致したものは件数の行にまとめる。開くと、各行で明細と対応する記録の日付・時刻・店名・金額を比べられ、登録済みのレシートへも移動できる。照合を更新した後も、保存済みの自動照合の結果を表示する
- 明細待ちには、設定で同じ明細サービスを選んだ支払元の、まだ照合していない支出だけを表示する。現金、サービス未設定の口座、確認済みの支出は含めない
- 確認が必要なものが0件の時は、「確認が必要な明細はありません」と✓で示す
- 照合タブのバッジに、要確認・記録なし・反映失敗の合計件数を出す

### 明細の取り込み

照合画面の「明細CSVを取り込む」を開いて始めます。入力は明細サービスとCSVファイルだけです。支払元の選択や、設定での事前の対応付けは求めません。支払元が1件もなくても照合結果まで進めます。

1. 明細サービスを選ぶ
2. CSVファイルを選び、「取り込んで照合」を押す
3. 照合画面に戻り、確認が必要な明細から見る

- 受け付ける形式は、PayPayカードの確認済みPayPayクレジット・1回払い、三井住友カードVpassと楽天カードの通常1回払い。イオンカードは形式が未確認のため選べない。条件は[明細形式の確認記録](STATEMENT_FORMATS.md)を参照してください
- 不確かな行は購入として扱わず、行番号と一般的な理由を表示する
- 解析、原本の保存、明細行の保存、照合はすべて端末内で行う。CSVを外部やAIへ送らない

### 要確認の詳細

「確認してください」の行を開くと、その場で縦に比べて判断できます。一覧の位置と他の明細を見失わないよう、別の画面へは移りません。

```text
△ スーパーみどり                ¥3,284 ▾
  9/29 · 金額が¥50違います
┌──────────────────────────────┐
│ 明細：2026-09-29 · スーパーみどり · ¥3,284 · PayPayカード │ ← 灰色の面
└──────────────────────────────┘
┌──────────────────────────────┐
│ 家計簿：2026-09-28 · スーパーみどり · ¥3,234 · 楽天カード │ ← 候補ごとの枠
│ 差分：日付差 2026-09-29 / 2026-09-28 · 金額差 ¥50（明細 ¥3,284 / 家計簿 ¥3,234）│ ← 警告色
│ [            同じ支出            ]  ← 主要    │
│              別の支出                         │
└──────────────────────────────┘
```

- 違う値は「差分：」として警告の色で示す
- 候補は、レシートと手入力の支出から探す。支払元では絞らず、候補の支払元は参考として表示する
- 金額の差は、利用者が「同じ支出」を選んだ時だけ反映する。カテゴリを分けた取引の総額だけを変える操作は拒否する
- 「別の支出」は、選んだ候補との組み合わせだけを除外する
- 照合の後に関係する支出や対応付けが変わった場合は、画面の更新を促す
- 反映に失敗しても判断は残し、「反映を再試行する」を表示する

### 記録なしの明細

候補がない明細は、日付・店名・金額を引き継いで「支出として登録」できます。

- カテゴリと支払元を選んで登録する。支払元を選ぶのはこの時だけ
- 同じ明細サービスを設定した支払元が1件なら、それを初めから選んでおく。支払元がない時は「支払元がありません」と表示し、その場で追加できる
- カテゴリは端末内の過去の確認結果から提案する。その場でカテゴリを追加した後も、明細の内容を保持する
- 返金には、支出として登録する操作を表示しない

### 予算

- ホームでは「使用額 / 予算額」と残り、進み具合のバーだけを見せる
- 予算の詳細では、カテゴリ別の予算額、使用額、残額、使用率を1行ずつ表示する
- 毎月の基本予算を通常の編集対象にする。選んだ月だけ変える操作と、変更を解除して基本予算へ戻す操作を、予算の詳細から選べる
- 0円の予算と未設定を区別する
- 高度な封筒式予算（Envelope budgeting）のUIは通常の画面に持ち込まない

### 設定

まとまりごとに見出しを付けて並べます。家計簿の管理は1行ずつの入口にし、タップすると管理画面へ進みます。カテゴリや口座の全件をここに展開しません。

```text
設定
家計簿
┌──────────────────────────────┐
│ カテゴリ                       › │
│ 支払元                         › │
│ 予算設定                       › │
│ 定期登録                       › │
└──────────────────────────────┘
データ
┌ バックアップと端末データ ─────┐
│ 最終書き出し生成日時：…          │
│ △ 復旧に備えてバックアップを…   │ ← 古い時だけ警告色
│ [   バックアップを書き出す   ]   │
│ [バックアップを読み込む] [切り替え前に戻る] │
│ ▸ バックアップについて           │
│ ▸ 原本の整理・全削除             │ ← 危険色
└──────────────────────────────┘
▸ 家計簿の読み込み・切り替え
写真の読み取り
┌ AI利用 ───────────────────────┐
│ 利用状況・ログイン・Passkey      │
└──────────────────────────────┘
アプリ
┌ アプリ情報 ───────────────────┐
│ □ 開発者向け機能を表示           │
└──────────────────────────────┘
家計簿と画像はこの端末に保存されます。…
```

- 支払元の管理画面で、各支払元の種類と明細サービスを設定する
- バックアップの書き出しを最も目立つ操作にし、書き出しが古い時は警告色の行で知らせる
- バックアップの詳しい説明と、原本の削除・全削除は折りたたむ。全削除などデータを消す操作は危険色で示す
- 開発者向けの機能はアプリ情報の中に置く

### バックアップと端末データ

- 最後にバックアップファイルを作った日時、ブラウザーの保存量の目安、保存維持の状態を示す。作った日時は、Files等への保存の完了ではないことを説明し、`.kmb` を端末の外へ保存するよう案内する
- `.kmb` は暗号化されていないため、他人へ渡さないよう伝える
- 復元では現在の家計データと混ぜず、新しい保存先へ読み込んでから切り替える。復元前のデータへ戻る操作を用意する
- 画像・CSV原本の削除では、削除件数と保存容量を表示し、削除後は原本を確認できなくなることを明示してから実行する。確認済みの値、明細行、照合結果、判断の記録は消さない
- 端末内の家計データの全消去には、確認と「すべて削除」の入力を求める。Cloud account、Passkey、契約、AI利用の権限には影響しないと説明する
- 復元中に読み込めない孤児の家計簿が見つかった場合は、アプリからの全消去を止める。元のデータをバックアップした後に、ブラウザーのサイトデータを削除するよう案内する。この削除は同じoriginの他のデータやログイン状態にも影響することがある

詳しくは[バックアップと復元](LOCAL_BACKUP.md)を参照してください。

### AIアカウント

- 家計簿、手入力、明細の取り込みと照合は、ログインせずに使える。写真の読み取りとカテゴリの提案にだけ、Passkeyでのログインが必要
- ログアウトしても端末内の家計データは消さない。そのことを画面で伝える
- 利用枠と今月の利用回数を表示する

| 画面 | 戻る・キャンセルの行き先 |

| 入力途中の追加ダイアログ | 元の入力画面（入力は保持） |

## 文言

| 使う | 使わない |

## エラーの伝え方

「エラーが発生しました」だけにしません。何が起きたかと、次にできることを書きます。

- 写真から金額を読み取れませんでした → 金額の入力欄へ移動する
- 明細の形式を確認できませんでした → 対応しているサービスとファイルの例を表示する
- 家計簿に保存できませんでした → 入力を失わず、再試行できるようにする
- 写真を読み取れませんでした → 画像を保持し、後で読み取り直せるようにする
- カテゴリを提案できませんでした → 未分類のまま利用者が選べるようにする
- AIアカウントからログアウトしました → 端末内の家計データはそのまま使えることを伝える
- 今月の読み取り回数の上限に達しました → 画像を端末に残し、手入力へ進めるようにする

## アクセシビリティ

- 本文は16 px以上を基準にする。補足は13〜14 pxとし、それより小さい文字はナビのラベル（12 px）に限る
- 文字と背景のコントラストは4.5:1以上にする。24 px以上の大きな文字は3:1以上でよい
- タップできる場所は44 CSS px以上にする
- フォーカスの表示を消さない
- フォームには必ずラベルを付ける。placeholderをラベルの代わりにしない
- アイコンだけのボタンには読み上げ名を付ける
- 成功・警告・エラーを、アイコンと文言でも区別する
- 端末の「視差効果を減らす」設定では、アニメーションを止める
