# UX

この文書は、本番アプリ `apps/pwa` の画面構成と操作の基準です。見た目の決まりは[デザイン](DESIGN.md)に定めます。保存するデータと実機確認の手順は[ローカル利用フロー](LOCAL_FIRST_FLOW.md)を参照してください。

## 位置づけ

この版は2026年10月のUI刷新で定め、同月に「台帳と印鑑」の見た目（あんず色、帳簿の行）へ改めた**目標の設計**です。現行の画面はまだ一部しか追いついていません。各画面は「移行状況」の順に、小さなPull Requestで置き換えます。実装と食い違う場合は、この文書を正とします。この文書を変えずに、画面側で例外を増やさないでください。

## 利用者と最優先

主な利用者は、ITに詳しくない家族です。

- 毎日の記録を、迷わず少ない操作で終えられること
- 確認が必要なものだけに気づけること
- 開くたびに「明るく、親しみやすく、読みやすい」と感じられること

機能をたくさん見せるより、次に何をすればよいかが分かることを優先します。

## UX原則

### スマートフォンで完結する

- 主な操作は親指が届く画面の下半分に置く。ナビは画面下に固定する
- タップできる場所は44 CSS px以上にする
- 横スクロールを使わない。表ではなく1行のリストを使う
- 撮影・写真選択までの操作を最短にする

### 正常なものを見せすぎない

明細照合では、自動で一致した取引を一件ずつ確認させません。件数で示し、必要な時だけ開けるようにします。先に見せるのは次の3つです。

1. 反映に失敗したもの
2. 要確認
3. 記録なし

### 技術を意識させない

Gemini、Jev、Actual、Rules、confidence等の内部名を通常の画面に出しません。利用者に伝えるのは結果です。

- 読み取りました
- 確認してください
- 登録しました
- 一致しました

写真からの読み取りとカテゴリ提案は、補助として「AIで読み取る」と表示して構いません。分類の学習やルールの適用は裏で行い、必要な時だけ「いつもの分類」等の短い説明を添えます。

### 判断の理由を見せる

照合の確認画面では、明細と記録の日付・金額・店名を縦に並べ、どこが違うか、なぜ候補になったかを示します。

### 入力を失わない

戻る、キャンセル、カテゴリや口座の途中追加、オフライン、保存失敗のどの場合も、入力した内容を不必要に失いません。破棄する時は、入力が消えることを伝えて確認します。

### 状態を色だけで伝えない

一致・要確認・記録なし・失敗は、必ず記号と文言を色に添えます。

| 状態 | 記号 | 文言の例 | 色の役割 |
| --- | --- | --- | --- |
| 一致 | ✓、「済」の印 | 自動で一致 / 照合済み | success（朱） |
| 要確認 | △ | 金額が¥50違います | warning（藍） |
| 記録なし | ! | 記録が見つかりません | missing（紫） |
| 失敗 | ! | 反映できませんでした | danger（深紅） |

「不正」「不正利用」とは書きません。対応する記録がない理由には、レシートの紛失、オンライン決済、利用日と計上日の差、返品などがあるためです。

### 自分の端末のデータだけを扱う

家計データは利用者の端末に保存します。家族一覧や他の利用者の支出は表示しません。

## 情報設計

### 下部ナビ

画面下に固定し、5つの枠を置きます。移動先は4つです。中央の「＋追加」は移動先ではなく、どの画面からでも記録を始めるための主要操作です。

```text
[ホーム] [記録] [ ＋ 追加 ] [照合] [設定]
```

- 中央の「＋追加」は大きな角丸の四角のボタンにして、ナビから少し浮かせる。ラベルは「追加」、読み上げ名は「記録を追加」
- 照合タブには、確認が必要な件数（要確認＋記録なし＋反映失敗）をバッジで表示する。読み上げ名にも件数を含める（例：「照合（確認が必要 6件）」）
- 選択中のタブは、色に加えて太字と `aria-current="page"` で示す
- 入力・確認・詳細など1つの作業に集中する画面でも、ナビは表示したままにする。入力は端末に自動で保存されるため、途中で別のタブへ移っても失われない。上部の「戻る」（新規入力では「キャンセル」）と、ナビの上に固定した主要ボタンで操作する
- 口座、予算、検索、定期登録などを理由に、ナビの移動先を増やさない

### 配置ルール

- 1画面の主要ボタンは1つ。ナビがある画面では「＋追加」がそれにあたる
- 一覧は1行表示にし、タップして詳細を開く
- 概要の画面に全部の詳細を置かない。概要からタップして詳細へ進む
- 日常的に触らない管理機能は設定へ寄せる
- 一覧は帳簿のように罫線で区切った行で並べ、まとまりには小さな見出しを付ける。1件ごとにも、まとまりごとにも面を作らない。面で囲うのは「確認すること」の箱など、[デザイン](DESIGN.md#台帳行とまとまり)で決めた場所だけにする
- 入力画面も、入力欄の箱を並べず、1項目を1行にした「帳簿の行」で組む
- 未実装の機能への入口は表示しない。同じ機能への主要な入口を重複させない

### PCでの表示

家族がPCのブラウザーで、明細CSVの取り込みや月のふり返りをまとめて行う場面を想定します。画面の幅が1024 CSS px以上の時に、同じ画面と同じ操作をPCに合う配置で見せます。機能・文言・画面の順序はスマートフォンと変えません。

```text
┌──────────────┬──────────────────────────────────────────┐
│ KakeiMatch   │ [‹]  2026年10月  [›]      支出の内訳            │
│              │ 今月使ったお金            ■■■■■■■■□□□□ (帯) │
│ [＋ 記録を追加]│ ¥82,430                   ● 食費 37% ● 日用品 │
│              │ 収入 │ 収支                ▸ すべてのカテゴリ  │
│ ⌂ ホーム      │ |||||||||||¦||||  (日の目盛り)                  │
│ ☰ 記録        │ ┌ 確認すること 6 ─────┐                        │
│ ✓ 照合    (6) │ │ △ スーパーみどり …  │                        │
│              │ └────────────────────┘                        │
│              │ 最近の記録 ──── すべて >                       │
│ ⚙ 設定        │ スーパーみどり      −¥3,284                    │
└──────────────┴──────────────────────────────────────────┘
```

- 下部ナビの代わりに、画面の左に固定したサイドナビを置く。移動先は下部ナビと同じ4つで、増やさない
- 「＋ 記録を追加」はサイドナビの一番上に、文字付きの主要ボタンとして置く。設定はサイドナビの一番下に置く
- 照合のバッジ・読み上げ名・`aria-current="page"` は下部ナビと同じにする
- ホームは2列にする。左に今月の支出・予算の目盛り・確認することの箱・最近の記録、右に支出の内訳を置く
- 記録一覧・照合・設定・入力・詳細は1列のまま、読みやすい幅（最大760 px）で中央に置く。横に広げて1行を長くしない
- 記録の種類を選ぶシートは、画面の中央に開くダイアログにする。閉じ方（×、背景のクリック、Escキー）は同じ
- 入力画面の「登録する」は、画面下に固定した帯の右側に置く
- マウスのホバーで行やナビの背景を変え、押せる場所を分かりやすくする。ホバーしないと出てこない操作は作らない
- キーボードだけでも、サイドナビから本文へTabで移動して操作できるようにする。読み上げとTabの順はスマートフォンと同じ（ホーム・記録・記録を追加・照合・設定）にする

今後の検討：記録一覧と詳細、照合の一覧と比較を左右に並べる2ペイン表示は、PCでの利用が増えてから決めます。それまでは、詳細へ進むと一覧を置き換える現在の動きを保ちます。

## 画面

以下のワイヤーフレームは幅375〜390 CSS pxのスマートフォンを想定しています。金額・店名・件数はすべて架空の例です。「>」はタップで詳細へ進む行、「[ ]」はボタン、「( )」は選択ボタンまたはカテゴリのアイコンを表します。

### ホーム

「今月どうなっているか」と「次に何をするか」が数秒で分かる画面です。上から次の順に並べます。

```text
[‹]        2026年10月        [›]
今月使ったお金
¥82,430                              ← 画面でいちばん大きな数字
収入 +¥250,000 │ 収支 +¥167,570
予算 ¥120,000              残り ¥37,570 >
|||||||||||||||||||¦|||||||||||        ← 1日1本の目盛り。¦ は今日
1日   今日18日 · 目安より ¥12,753 多め   31日
┌ 確認すること 3              照合へ ┐
│ △ セブン-イレブン 本町店    −¥1,280 │
│   金額が¥50違います                  │
│ ! AMAZON.CO.JP              −¥4,378 │
│   記録が見つかりません               │
│ △ ENEOS 中央通りSS          −¥5,600 │
│   日付が2日ずれています              │
└──────────────────────────────┘
(済) 今月の 41件 は自動で照合済みです
支出の内訳          すべてのカテゴリ >
■■■■■■■■■■■■■■■■■■■■■■■  ← 帯グラフ
● 食費    37%   ● 日用品  15%
● 交通    12%   ● その他  36%
最近の記録                すべて >
スーパーみどり 10/18・楽天カード −¥3,284
カフェこもれび 10/18・PayPayカード −¥1,080
現金 → 銀行口座 10/17・振替    ¥10,000
[ホーム] [記録] [＋追加] [照合] [設定]
```

- 当月以外を表示している時は、月の表示の下に「当月へ戻る」を出す
- 今月の支出の数字を画面でいちばん大きくする。その下に収入と収支を罫線で区切って並べる
- 予算の概要は、月の日数分の目盛りと残り（超過時は「超過 ¥…」）として置く。今日の位置に線を引き、「目安より ¥… 多め／少なめ」を文字で書く。目安は予算額を月の日数で割り、経過日数を掛けた額にする。「残り ›」を押すとカテゴリ別の予算と「この月の予算を変更」を開く。予算が未設定の月は「予算を設定する」と表示する
- 確認が必要な明細が1件以上ある時だけ、「確認すること」の箱を表示する。見出しに件数を出し、反映失敗・要確認・記録なしの順に最大3件を1行ずつ並べる。行を押すと照合のその明細を開く。4件以上ある時は「照合へ」から残りを見る。0件の時は箱を出さない。明細を一度も取り込んでいない時だけ、照合への案内行「明細を取り込んで自動で照合する」を補助として1つ表示する
- 自動で照合済みのものは、「済」の印と件数の1行だけにする
- 支出の内訳は横に長い帯グラフにする。上位3カテゴリと「その他」の最大4区分にし、凡例に割合を文字で書く。全カテゴリの金額と割合は「すべてのカテゴリ」を開いて見せる
- 最近の記録は3件まで。続きは「すべて」から記録一覧へ進む

### ＋追加（記録の種類を選ぶ）

「＋追加」を押すと、今の画面の上に、下からせり出すシートを開きます。支出の方法も含めて、1枚のシートで選べるようにします。

```text
何を記録しますか？                    [×]
┌──────────────────────────────┐
│ [カメラ] レシートを撮る            > │ ← いちばん大きい
│          写真を残して、品目まで読み取れます │
└──────────────────────────────┘
┌ 写真から ──────┐┌ 支出を手入力 ──┐
│ 保存したレシート ││ レシートなし    │
└────────────────┘└────────────────┘
┌ 収入 ──────────┐┌ 口座間の振替 ──┐
│ 給与・臨時収入  ││ 現金の引き出しなど │
└────────────────┘└────────────────┘
```

- 「レシートを撮る」を横幅いっぱいでいちばん大きく置き、カメラのアイコンだけを主要色で塗る。面は塗らない（下に見える「＋追加」と塗った面を重ねない）。残りの4つは同じ強さで2列に並べる
- 「レシートを撮る」はカメラを起動する。「保存した写真から」は写真の選択を開く
- ×（閉じる）、背景のタップ、Escキー、下へのスワイプ（80 px以上）でシートを閉じる。下の画面はそのまま残る
- シートを開いている間は、後ろの画面を操作できない（モーダル）

### 支出の入力（手入力・レシート共通）

手入力とレシートで同じ画面を使います。入力画面の上部で「全体」と「品目一覧」を切り替えられ、「登録する」はどちらの表示でも画面下に固定します。「全体」は基本項目を帳簿の行で表示し、「品目一覧」は画像・店名・日付などを隠して品目だけを上へ詰めます。

入力欄は箱を並べず、1項目を1行にした「帳簿の行」で組みます。左に項目名、右に値を置き、罫線で区切ります（見た目は[デザイン](DESIGN.md#帳簿の行で組む入力)）。

```text
キャンセル           支出を入力
[       全体       ][      品目一覧      ]
金額      ¥1,080                        ← 大きな数字・入力中は下線
店名      カフェこもれび
日付      10/18（日）        (今日) (昨日)
カテゴリ  外食  前回と同じ        すべて ›
支払元    PayPayカード                  ›
時刻・メモ  任意                         ›
品目      分けない（品目・値引き・税額） ›
くり返し  しない                        ›
──────────────────────────────
[            登録する            ]  ← ナビの上に固定
```

- 金額を最初の行にして、数字キーボード（`inputmode="numeric"`）を開く
- 日付は行の右の「今日」「昨日」で選べるようにする。それ以外の日は値を押して日付の入力で選ぶ
- カテゴリは1行にする。初めは同じ種類（支出・収入）で前回使ったカテゴリを入れ、「前回と同じ」と添える。前回がない時、または前回のカテゴリが非表示・削除済みの時は空欄にする。「すべて ›」を押すと下からシートを開き、アイコン付きのボタンを4列で並べた中から選ぶ（読み上げでは単一選択のラジオボタン）。シートの並びは、最近の記録（100件）でよく使うカテゴリの順にし、記録がない時は家計簿のカテゴリの順にする（設定のカテゴリ一覧と同じ順）。提案したカテゴリには「いつもの分類」と短く添える
- 検索・照合のカテゴリは選択欄のまま使う
- 支払元は、押すと下からシートを開いて選ぶ。支出ではクレジットカードを先に並べる
- 時刻・メモは1行に畳み、未入力なら「任意」と書いて、押すとその場で開く。品目（品目・値引き・税額）は「品目一覧」だけに表示し、「全体」では「分けない」「2品目・値引き1」のように要約した1行を置いて、押すと「品目一覧」へ移る。「品目一覧」では画像と基本項目を隠して品目編集までの縦スクロールを減らす
- 「くり返し」を毎月・毎週・毎年にすると、登録と同時に定期登録を作る。初めは「しない」にする。定期登録の一覧・変更・停止は設定で行う

品目一覧から登録する時に基本項目が不足している場合は、「全体」へ戻して不足した欄を確認できるようにします。品目やメモの入力は保持します。

日常的に直してもらう項目は、店名・日付・金額・カテゴリに絞ります。品目の細かな修正を日常の操作として求めません。

#### レシートの場合

1. 撮影または写真を選ぶと、まずレシートの原本を端末に保存する
2. 写真を小さく1行に表示し、その右に「AIで読み取る」を補助のボタンとして置く。読み取りは利用者が押した時だけ行う
   - 写真を押すと全画面で開く。タップした所を拡大し、もう一度タップすると元に戻る。指での拡大も使える
3. 読み取っている間は「読み取り中」の表示にする（下記）
4. 読み取ったら、写真の行に「✓ 写真から読み取りました／違うところだけ直してください」と表示し、各行に値を入れる
   - 品目のあるレシートでは、金額の行の右端に、品目と値引きの合計と合っているかを小さく添える。外税のレシートでは、品目と値引きに読み取った税額を足して合えば合っているとする。合っていれば「✓ 一致」、合わなければ「△ 差額あり」とだけ書く。読み上げ名には「品目と値引きの合計と一致」「品目と値引きの合計と¥50違います」のように中身を含める。品目がないレシートでは表示しない
   - 画像と照らし合わせてほしいところがある時は、警告の帯に件数と、1行ずつ「どこ（例：品目2「レタス」、合計金額）」と「なぜ（例：欠品のため金額が0円です）」を並べる。行を押すと該当する欄へ移動する。該当する欄の行の右端と、品目の名前の下には「△ 写真と確認」と文字でも示す（合計の不一致の「△ 差額あり」とは言葉を分ける）。各行の「確認した」、または該当する欄・品目の編集で、その行を消す。消した行は同じ読み取り結果を開き直しても出さない（再読み取りで元に戻る）
   - 時刻（任意の項目）、欠品などの0円の行、ポイント利用は、金額に影響しないか扱いが決まっているので要確認にしない。ポイント利用はクーポンと同じく値引き・調整にマイナスで入れ、合計金額はポイントを引いた後の支払額にする。全額をポイントで支払った写真のレシートは、合計0円のまま登録できる（手入力の支出は1円以上）
5. 読み取り済みの時は「再読み取り」とし、利用枠を使うことと入力が置き換わることを確認してから実行する

画像は10 MiBまで端末に保存します。AIの受け付け上限は6 MiBなので、それを超える画像は保存だけ行い、送信しません。読み取った値と利用者が確定した値は、内部で区別して保存します。

品目のあるレシートでは、全体のカテゴリを選ばせません。カテゴリは品目ごとに付け、カテゴリの行には「品目ごと」と、カテゴリ別の小計（例：食費 ¥2,324・日用品 ¥960）を表示します。行を押すと品目一覧へ移ります。品目のないレシートだけ、手入力と同じくカテゴリを1つ選びます。

#### 読み取り中

```text
キャンセル           レシート
[撮った写真（走査線が上下に動く）  ○ 読み取り中]
✓ 写真を保存しました
  この端末に。読み取れなくても消えません
◌ 文字を読み取っています
  数秒かかります
○ 品目をカテゴリに分けます
金額  ▭▭▭▭▭                     ← 仮の帯
店名  ▭▭▭▭▭▭▭
日付  ▭▭▭▭
品目  ▭▭▭▭▭▭
──────────────────────────────
[          読み取り中…          ]  ← 押せない
       待たずに手で入力する
```

- 読み取りを始めたら、撮った写真を大きめに表示して走査線を動かし、「読み取り中」の札を重ねる
- 「写真を保存しました」「文字を読み取っています」「品目をカテゴリに分けています」の3段階を行で示し、終わった段階に✓、進行中の段階に回転する印を付ける。進行中の段階には「数秒かかります」のように目安を添える
- まだ読めていない欄は仮の帯にする。文字を読み終えたら金額・店名・日付・品目名を先に表示し、カテゴリは分類できた品目から順に表示する。分類が終わっていない品目のカテゴリも仮の帯にする
- 読み取り中・分類中は「登録する」を押せない状態にし、「読み取り中…」「分類を待っています…」と文言で示す。代わりに「待たずに手で入力する」「分類を待たずに自分で選ぶ」を置き、待たずに先へ進めるようにする
- 読み取れなかった時は、段階の行を「! 読み取れませんでした」にし、写真は残っていることと次にできることを示す。主要ボタンは「もう一度読み取る」にして、同じ写真でAIの読み取りをやり直せるようにする。その下に文字のボタン「手で入力して続ける」を置き、説明の帯の中に「撮り直す」を置く。帯の文は「ぼやけや反射があれば撮り直してください。」のように短くし、「撮り直す」をスクロールせずに押せるようにする

  ```text
  ! 読み取れませんでした
  ┌ ! 写真から読み取れませんでした ───────┐
  │ ぼやけや反射があれば撮り直してください。│
  │ [撮り直す]                           │
  └──────────────────────────────┘
  [        もう一度読み取る        ]  ← 主要
          手で入力して続ける
  ```

- 「もう一度読み取る」の利用回数の数え方は、通常の読み取りと同じにする。利用回数の上限に達している時は「もう一度読み取る」を出さず、主要ボタンを「手で入力して続ける」にする
- 読み取り回数の上限やログインが必要な時も、写真を残したまま手入力へ進めるようにする
- 段階が変わるたびに、読み上げにも状態の変化を伝える。端末の「視差効果を減らす」設定では動きを止める
- キャラクターや経過秒数の表示は置かない。段階の行と文言だけで、今どこまで進んだかを伝える

#### 品目と値引き

「品目」の行を開くか、上部の「品目一覧」へ切り替えると、品目と値引きを入力できます。

```text
合計      ¥3,284              ✓ 品目と一致
内訳      ■■■■■■■■■■□□□□
          ● 食費 ¥2,324   ● 日用品 ¥960
国産たまご 10個      [● 食費]      ¥268
牛乳 1000ml          [● 食費]      ¥228
値引 · 鶏もも肉                    −¥100
トマト 3個           [● 食費?]     ¥398  ← 破線の札はAIの提案
  △ 品名が読みにくい
＋ 品目を追加   ＋ 値引き・調整   税額
```

- 品目一覧の上に、合計と品目の合計が合っているかの行と、カテゴリ別の小計の帯を置く
- カテゴリは品目ごとに付ける。AIの提案でまだ確定していないカテゴリは、破線の札に「?」を付けて示す。押すと確定・変更できる
- 品目数はタブ名へ表示しない。品目一覧そのものから把握できる情報を重ねて表示しない
- 閉じた品目は、品目名・カテゴリ・金額を1行に近い高さで表示する。タップした品目だけ編集欄を開き、別の品目を開いたら先に開いていた品目を閉じる
- AIで読み取った品目は最初は閉じて一覧性を優先する。手動で「品目を追加」した直後だけ、その新しい品目を自動で開く
- 値引き・調整も閉じた状態では内容・種類・金額をコンパクトに表示し、必要な時だけ開いて編集する
- 値引き額は正の数で入力する。加算の調整は種類で選ぶ
- 品目を削除するボタンは、編集欄のカテゴリの下に置く
- 入力欄から離れただけでは、現在編集中の品目を自動で閉じない
- 入力した合計金額を、品目の合計で上書きしない

### 収入・口座間の振替の入力

支出と同じ画面構成にし、項目だけを変えます。

- 収入：金額、内容、日付、収入カテゴリ、入金先、メモ、くり返し
- 振替：金額、日付、振替元、振替先、メモ。収入や支出とは区別して表示する。振替先の行の右に、振替元と入れ替えるボタンを置く
- 収入カテゴリの初めの値と「くり返し」の扱いは支出と同じにする
- 入金先・振替元・振替先では、銀行口座と現金を先に並べる

手入力の収入・支出で保存結果が不明な場合は、下書きを保持して入力を固定する。再試行中は「保存結果を確認しています…」と表示する。同じ登録IDの取引が下書きと異なる場合は、登録済みの日付・金額・内容・カテゴリ・口座・メモを表示し、「登録済みの内容で完了する」で利用者が確認してから下書きを片付ける。完了時にも再取得し、内容が変わっていれば再確認を求める。未登録と確認できた場合は入力を編集できる状態に戻す。読み取りに失敗した場合は入力を保持し、再試行を案内する。処理中以外はキャンセルできる。

### 入力途中でカテゴリ・口座を追加する

カテゴリを選ぶシートのボタン群の最後に「＋追加」を、支払元・入金先・振替元・振替先を選ぶシートに「支払元・口座を追加」を置きます。追加は小さなダイアログで行います。

- 支出からは支出カテゴリ、収入からは収入カテゴリだけを追加する。レシートの品目カテゴリにも同じ導線を使う
- 支払元の追加では、銀行口座・クレジットカード・現金・その他 / 未分類の種類を選べる
- 追加しても「入力へ戻る」を選んでも、元の入力画面へ戻る。日付・金額・店名・メモ・品目の入力を保持する
- 追加した後は一覧を再取得し、新しい項目を選択する。振替の片方から追加した場合は、もう片方の選択を保持する
- 追加には設定画面と同じフォームと保存処理を使う。名称変更、非表示、利用終了、削除は設定で行う

### 記録一覧

収入・支出・振替を同じ時系列で見る画面です。月では区切らず、新しい順に最大100件を表示します。先月の日付で登録した記録も、登録した直後にこの一覧で見つけられるようにするためです。月や期間で絞る時は検索を使います。

```text
記録                                [検索]
[すべて|支出|収入|振替]
口座・残高を見る                      >
┌╌ 確認待ち ╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┐  ← 破線の枠
╎ (レ) 未入力のレシート 1枚  確認する ╎
└╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┘
10月2日（金）                −¥4,364   ← 日付の見出し
(食) スーパーみどり            −¥3,284
     食費・牛乳とパン・レシート
(食) カフェこもれび            −¥1,080
     食費・PayPayカード
10月1日（木）              +¥243,180
(収) 給与                    +¥250,000
(振) 現金 → 銀行口座           ¥10,000
```

- 登録前のレシート・支出は「確認待ち」として一覧の先頭にまとめ、「確認する」から入力へ進む
- 日付ごとにまとめ、見出しに曜日とその日の収支（振替を除く）を出す。日付ごとに面で囲わず、見出しと罫線で区切る
- 1行の構成：左にカテゴリのアイコン、中央に店名または内容と補足、右に金額。支出・収入の補足はカテゴリまたは種類に続けて、メモがあればメモを表示し、メモがなければ支払元を表示する。画像付きのレシートなら末尾に「レシート」を付ける
- 行の読み上げ名には、見出しで省いた日付も含め、画面と同じくメモを支払元より優先する（例：「スーパーみどり · 10/2 · 食費 · 牛乳とパン · −¥3,284」）
- 「支出」タブでは、主な文字にメモを表示し、メモがない場合や空白だけの場合はカテゴリ名（未設定なら「支出」）を表示する。補足には店名と支払元を並べ、画像付きなら末尾に「レシート」を付ける。読み上げ名もこの順序に合わせ、日付を含める
- 金額は右揃えにし、等幅の数字で表示する。支出は「−¥」、収入は「+¥」に収入の色、振替は記号なしで補足に「振替」と書く
- 照合で確認が必要な明細の候補になっている記録は、補足の先頭に警告色で「△ 要確認」と示し、読み上げ名にも「要確認」を含める
- 種類の絞り込みは上部の切り替えで行う。店名や金額などの詳しい条件は検索を開いてから表示する
- 「口座・残高を見る」から残高を確認できる。口座の管理は設定で行う

### 記録の詳細・編集・削除

```text
‹ 記録一覧へ戻る
支出の記録
┌──────────────────────────────┐
│ 金額                    ¥3,284 │ ← 大きく表示
│ 日付                2026-10-02 │
│ 店名・支払先     スーパーみどり │
│ カテゴリ                  食費 │
│ 支払元              楽天カード │
│ メモ                      なし │
└──────────────────────────────┘
各項目をタップして編集する
           削除する              ← 文字だけの破壊的操作
```

- 戻る操作は画面の左上に置く。検索から開いた場合は「検索結果へ戻る」にする
- 振替では振替元口座と振替先口座を表示する
- レシート由来の記録も同じ構成にする。見出しは「支出の記録」で、金額・日時（時刻がある時）、「店名・支払先」、カテゴリ、支払元、メモ、状態（「✓ 家計簿へ登録済みです。」）を、上の例と同じ項目名と値の行で1つのまとまりに置く。メモがない時は「なし」と書く。レシート画像、購入内容（品目・価格・カテゴリ）、値引き・調整はそれぞれ折りたたんで段階的に開く
- 自動学習ルールを使って分類したレシートは、「分類の理由」を折りたたんで表示する。適用した店舗・品目、カテゴリ、適用時の根拠件数と一致率を示す。適用時の根拠snapshotがない過去レシートには表示しない
- 支出・収入では「編集する」ボタンを置かず、編集可能な行の右端に「›」を添える。行をタップすると編集画面のその項目へ移り、カテゴリなら選択を開く。品目別に分類した支出のカテゴリは品目一覧を開く。状態は編集できない。振替は「編集する」から開く
- 編集画面の主要ボタンを「変更を保存する」にする。保存・キャンセル後は元の詳細へ戻る
- 削除は確認してから行い、削除直後の10秒間は取り消せるようにする。詳細は[取引削除と取り消し](LOCAL_TRANSACTION_DELETION.md)を参照してください

### 照合

```text
照合                         [照合を更新する]
! 家計簿への反映が完了していません [反映を再試行する]  ← 失敗がある時だけ
┌△ 要確認┐┌! 記録なし┐┌✓ 自動で一致┐
│  4件   ││   2件    ││    76件    │
└────────┘└──────────┘└────────────┘
明細待ちの支出 3件（明細を取り込むと照合します）
┌──────────────────────────────┐
│ ⬆ 明細CSVを取り込む          ▸ │  ← 開くとサービスとファイルを選ぶ
└──────────────────────────────┘
確認してください
スーパーみどり            ¥3,284 ›
△ 9/29 · 金額が¥50違います
カフェこもれび              ¥880 ›
△ 9/26 · 候補が2件あります
オンラインストア          ¥2,980 ›
! 9/18 · 記録が見つかりません
(済) 自動で一致した内容を見る（76件） ›
```

- 上部に件数を3つに区切った枠で並べる。要確認と記録なしは状態の色を背景にし、自動で一致は背景を付けず朱の数字にする。読み上げ用に「照合の結果：自動で一致 2件 · 要確認 1件 · 記録なし 2件 · 明細待ち 0件」の文を添える
- 反映に失敗した判断は、件数の枠より上に危険色の帯で示す
- 「確認してください」には、要確認、記録なしの順に並べる。各行の補足には、日付と何が違うかを短い文で書く（金額が¥50違います、日付が3日ずれています、候補が2件あります、記録が見つかりません）
- 自動で一致したものは件数の行にまとめる。開くと、各行で明細と対応する記録の日付・時刻・店名・金額を比べられ、登録済みのレシートへも移動できる。照合を更新した後も、保存済みの自動照合の結果を表示する
- 明細待ちには、設定で同じ明細サービスを選んだ支払元の、まだ照合していない支出だけを表示する。現金、サービス未設定の口座、確認済みの支出は含めない
- 確認が必要なものが0件の時は、「確認が必要な明細はありません」と✓で示す
- 照合タブのバッジに、要確認・記録なし・反映失敗の合計件数を出す

### 明細の取り込み

照合画面の「明細CSVを取り込む」を開いて始めます。入力は明細サービスとCSVファイルだけです。支払元の選択や、設定での事前の対応付けは求めません。支払元が1件もなくても照合結果まで進めます。

1. 明細サービスを選ぶ
2. CSVファイルを選び、「取り込んで照合」を押す
3. 照合画面に戻り、確認が必要な明細から見る

- 受け付ける形式は、PayPayカードの確認済みPayPayクレジット・1回払い、三井住友カードVpassと楽天カードの通常1回払い。イオンカードは形式が未確認のため選べない。条件は[明細形式の確認記録](STATEMENT_FORMATS.md)を参照してください
- 不確かな行は購入として扱わず、行番号と一般的な理由を表示する
- 解析、原本の保存、明細行の保存、照合はすべて端末内で行う。CSVを外部やAIへ送らない

### 要確認の詳細

「確認してください」の行を開くと、その場で縦に比べて判断できます。一覧の位置と他の明細を見失わないよう、別の画面へは移りません。

```text
△ スーパーみどり                ¥3,284 ▾
  9/29 · 金額が¥50違います
┌──────────────────────────────┐
│ 明細：2026-09-29 · スーパーみどり · ¥3,284 · PayPayカード │ ← 灰色の面
└──────────────────────────────┘
┌──────────────────────────────┐
│ 家計簿：2026-09-28 · スーパーみどり · ¥3,234 · 楽天カード │ ← 候補ごとの枠
│ 差分：日付差 2026-09-29 / 2026-09-28 · 金額差 ¥50（明細 ¥3,284 / 家計簿 ¥3,234）│ ← 警告色
│ [            同じ支出            ]  ← 主要    │
│              別の支出                         │
└──────────────────────────────┘
```

- 違う値は「差分：」として警告の色で示す
- 候補は、レシートと手入力の支出から探す。支払元では絞らず、候補の支払元は参考として表示する
- 金額の差は、利用者が「同じ支出」を選んだ時だけ反映する。カテゴリを分けた取引の総額だけを変える操作は拒否する
- 「別の支出」は、選んだ候補との組み合わせだけを除外する
- 照合の後に関係する支出や対応付けが変わった場合は、画面の更新を促す
- 反映に失敗しても判断は残し、「反映を再試行する」を表示する

### 記録なしの明細

候補がない購入明細は、日付・店名・金額を引き継いで支出または振替として登録できます。

- 支出はカテゴリ、振替は振替先を選ぶ。支払元は明細サービスに対応するカードへ固定し、選択欄を出さない
- 明細サービスに対応した支払元がなければ、登録時に同名のカードを対応付け、なければ作成する。複数の対応がある場合は設定の修正を促す
- 支出では「支出の計算に含めない」を指定できる。手入力時や、登録済みの記録・レシートの詳細からも変更でき、記録と口座残高は保持する
- カテゴリは端末内の過去の確認結果から提案する。その場でカテゴリや振替先を追加した後も、明細の内容を保持する
- カテゴリの「すべて ›」は4列の選択画面を開く。全期間の支出記録で使用回数が多い順に上から並べ、分割記録では各カテゴリを1回ずつ数える。同数なら通常のカテゴリ順を維持する。基本カテゴリは小さなスマートフォンでもスクロールせず一覧できる高さに収める
- 「登録しない」で確認を終えられる。候補がある明細や返金でも選べる。判断した明細は折りたたんだ履歴に残す
- 返金には、支出・振替として登録する操作を表示しない

### 予算

- ホームでは全体予算と残り、日の目盛り、目安との差を見せる。カテゴリ別の内訳は「残り ›」から開く詳細に出す
- 予算設定では、まず1か月の全体予算を入力できるようにする。カテゴリ別の内訳は任意とする
- カテゴリ別の内訳を使う場合だけ、カテゴリごとの予算額、使用額、残額、使用率を表示する
- カテゴリ別予算の合計が全体予算と一致しない状態は保存させない
- 毎月の基本予算を通常の編集対象にし、選んだ月だけ全体予算と内訳を上書きできる
- 0円の予算と未設定を区別する
- 高度な封筒式予算（Envelope budgeting）のUIは通常の画面に持ち込まない

| バックアップと復元 | バックアップの書き出しと復元、復元・同期後だけ「変更前のデータに戻す」、保存先の説明、折りたたんだ「バックアップについて」と「既存の家計簿を取り込む」 |
| 画面ロック | 画面ロックの設定（入口の右には「オン」「オフ」） |
| 原本の整理・全削除 | 原本の整理と、この端末の家計データの全削除 |
| ログイン・利用状況 | ログイン、利用回数と進み具合のバー、Passkey、ログアウト、アカウント削除（入口の右には今日または今月の回数） |
| 外観 | 表示モードをライト・ダーク・システムから選ぶ。変更はすぐ反映し、このブラウザーに保存する。初期値はシステム |

- 支払元の管理画面で、各支払元の種類と明細サービスを設定する
- バックアップの書き出しを最も目立つ操作にし、書き出しが古い時は△の付いた警告色の1行で知らせる。書き出しと復元の操作は「バックアップと復元」のページにまとめる。通常は保存済みの家計簿を自動で開き、選択できない場合だけ家計簿の選択を表示する
- 全削除などデータを消す操作は、入口も含めて危険色で示す
- AIの運用費用は管理者専用の管理画面に置き、利用者向け設定には表示しない
- アプリ情報の「端末内の診断」は、家計内容を含まない固定コードの処理結果を確認してからコピー・書き出しできる。自動送信しない。オフラインでも使え、記録だけを消す操作を置く

### 設定の奥の画面（カテゴリ・支払元・予算・定期登録・分類ルール・検索）

設定から入る一段深い画面も、ホームや記録と同じ部品で組み立てます。

- 戻る操作は左上の「‹ 設定」「‹ カテゴリ」のような文字のボタンにする。一覧は設定へ、詳細や編集はひとつ上の画面へ戻る
- 一覧はアイコン付きの1行（補足と右端の ›）を罫線で区切り、見出しでまとめる。非表示や利用終了のものは薄く表示するか、最後の1行にまとめる
- 詳細は上部にアイコンと名前を大きく出し、項目名と値を左右に並べる
- 主要な操作（追加・編集・保存）はナビの上に固定した1つのボタンにする。削除は危険色の文字だけにする
- 画面を開いた直後に別の画面へ移った場合、遅れて終わった古い描画は捨てる

| 画面 | 内容 |
| --- | --- |
| カテゴリ | 上部の切り替えで支出・収入を選ぶ。基本の支出カテゴリは初回利用時に自動で用意する。各行に記録の件数を出し、記録が多い順（入力画面のボタンと同じ順）に並べる。「カテゴリを追加」を主要ボタンにする |
| カテゴリの詳細 | 種類・グループ・状態・今月の金額・使われている記録を並べる。「カテゴリを非表示にする」は補足付きの行。記録がない時だけ削除できる |
| 支払元・口座 | 上部に利用中の口座の合計を出し、種類ごと（銀行口座・クレジットカード・現金・その他）に並べる。各行に明細サービスと残高（カードは差引額）を出す。利用終了した口座は折りたたむ |
| 支払元の詳細 | 残高・種類・明細サービス・状態・記録の件数を並べ、最近の記録2件と「口座の記録を見る」を置く。記録も残高もない時だけ、確認付きで完全に削除できる |
| 予算 | 支出カテゴリ全件を1画面に並べ、その場で金額を入力して「基本予算を保存」または「この月の予算を保存」でまとめて保存する。上部の切り替えで毎月の基本予算と選んだ月だけの変更を選ぶ。空欄は予算なし、0円は0円の予算として区別する。月だけ変更しているカテゴリには「基本に戻す」を出す |
| 定期登録 | 各行に頻度・次回の日付・自動登録の有無と金額を出す。詳細は項目名と値の並び |
| 分類ルール | 自動学習した品目・店舗の分類を根拠件数と一致率付きで表示する。詳細から有効状態と適用カテゴリを変更でき、削除は確認して学習履歴を残したまま適用を止める |
| 記録を検索 | 上部の検索欄で店名・メモ・品目を探す。期間・種類・カテゴリ・口座・金額は小さなボタンで示し、押すと詳細条件が開く。結果は記録一覧と同じ1行表示で、件数と合計を出す |
| ログイン・利用状況 | 設定の「写真の読み取り」の入口から進む。ログイン状態、読み取り回数（ログイン中は今月、ログインしていない時は今日）と進み具合のバー、Passkeyの一覧、ログアウトを置く。ログアウトしても家計簿は消えないことを書く |

定期登録の開始日が当日以前の場合は、到来済みの未登録分を確認します。1件なら保存時に補完し、複数件なら保存前に期間・件数・合計金額を示して「全件」「今月分から」「キャンセル」を選べるようにします。「今月分から」を選んでも元の開始日は保持します。

補完直後は今回作成した記録をまとめて元に戻せるようにします。定期登録の詳細にも過去分の生成履歴を残し、日付を選んで削除できるようにします。編集済みの記録は残し、その理由を文字で示します。削除や取り消しをしても、同じ対象日を保存し直すだけで再生成しません。

### バックアップと端末データ

- 最後にバックアップファイルを作った日時、ブラウザーの保存量の目安、保存維持の状態を示す。作った日時は、Files等への保存の完了ではないことを説明し、`.kmb` を端末の外へ保存するよう案内する
- `.kmb` は暗号化されていないため、他人へ渡さないよう伝える
- 復元では現在の家計データと混ぜず、新しい保存先へ読み込んでから切り替える。復元前のデータへ戻る操作を用意する
- 端末データの更新に失敗した時や、このアプリより新しいデータを検出した時は、家計画面と家計操作を隠して救出画面を表示する。診断を見られるよう設定画面への移動は残す。対象プロフィールの対応済みrecord kindだけを読み取り専用で書き出し、未対応の種類の除外件数はmanifestへ記録する。修正版へ更新してから再読み込みするよう案内する。救出ファイルは復元用ではなく、Actual Budgetの家計簿・画面ロック設定・クラウドのログイン情報・同期の暗号鍵を含まない
- 画像・CSV原本の削除では、削除件数と保存容量を表示し、削除後は原本を確認できなくなることを明示してから実行する。確認済みの値、明細行、照合結果、判断の記録は消さない
- 端末内の家計データの全消去には、確認と「すべて削除」の入力を求める。Cloud account、Passkey、契約、AI利用の権限には影響しないと説明する
- 復元中に読み込めない孤児の家計簿が見つかった場合は、アプリからの全消去を止める。元のデータをバックアップした後に、ブラウザーのサイトデータを削除するよう案内する。この削除は同じoriginの他のデータやログイン状態にも影響することがある

詳しくは[バックアップと復元](LOCAL_BACKUP.md)を参照してください。

### 端末間の同期

- 設定の「データ」の入口の先頭に「ほかの端末と同期」の行を置き、押すとダイアログで説明と手順を出す。自分の2台の間で、家計簿をどちらか一方にそろえる。取引ごとの合併はしない
- サーバーを通さず、同じWi-Fiにつないだ2台の間で直接、暗号化して送ることを書く
- 流れ
  1. 1台目で「この端末から始める」を押すと、最初のコードをQRコードで出す。カメラのない端末へ渡せるよう、「文字のコードで渡す」を開くと同じコードを文字でも出し、「コードをコピー」を置く
  2. 2台目で「相手の端末のコードを読む」を押し、「カメラで読む」か、貼り付けたコードで続ける。2台目は返事のコードを同じ形で出す
  3. 1台目で返事のコードを読む
  4. つながったら、両方の端末に「この端末」「相手の端末」の行を並べ、それぞれの取引の件数と最新の取引日を出す。「この端末の家計簿にそろえる」「相手の家計簿にそろえる」から選ぶ
  5. 選ばれた側が家計簿を送り、進み具合を％で出す。受け取った側は、自分の端末で選んだ時はそのまま、相手の端末で選ばれた時は「置き換える」を押してから切り替え、読み込み直す。送った側には「相手の端末の家計簿を、この端末の家計簿にそろえました。」と出す
- 今の同期の状態
  - 設定の「ほかの端末と同期」の行の右に「未同期」「10月7日にそろえました」「10月7日のあと変更あり」と出す。「変更あり」は、最後の同期のあとにこの端末の取引が1件でも変わった時（全取引から作る指紋で比べる）
  - ダイアログの上に「最後の同期：10月7日 14:32（iPhoneを、この端末の家計簿にそろえました）」と、そのあと変わったかを出す
  - つながった時に2台の家計簿が同じなら「2台の家計簿は同じです。そろえる必要はありません。」と出す
  - 終わった時は、送った側に「✓ そろいました」と件数・最新日を、受け取った側には読み込み直した後に「✓ 相手の端末の家計簿にそろえました（取引◯件・最新◯月◯日）。」を出す
  - 同期の記録は端末ごとの設定で、バックアップには含めない
- カメラでの読み取りは、ブラウザーにQRの読み取り機能があればそれを使い（MacやAndroidのChrome）、なければjsQRで読む。細かいコードを読めるよう、カメラには高い解像度を求める
- 読む段階を間違えたコード、欠けたコード、KakeiMatchのものでないコードは、何が違うかを文で伝える
- 返事のコードを読んでから20秒たってもつながらない時は、待ち続けずに「つながりませんでした」と出し、確かめること（同じWi-Fiか、Macのローカルネットワークの許可と再起動、ルーターの端末どうしの通信を止める設定）を並べる
- 接続が切れた時や、受け取った家計簿が欠けていた時は、家計簿を変えていないことを伝えて、はじめからやり直してもらう
- 置き換えられた側の元の家計簿は、その端末の「変更前のデータに戻す」で戻せることを、選ぶ画面と確認の時に書く

### AIアカウント

- 家計簿、手入力、明細の取り込みと照合は、ログインせずに使える
- 写真の読み取りとカテゴリの提案も、ログインせずに1日5回（毎日午前0時（日本時間）に戻る）まで使える。Passkeyでログインすると、プランの回数（月ごと）で使う
- ログインせずに初めてAIを使う時だけ、「確認しています」のダイアログでロボットでないことを確かめる。多くは自動で終わる。「やめる」を押しても写真は残り、手入力やもう一度の読み取りへ進める
- ログインしていない時は「今日のAI読み取り 1 / 5回 · 登録なし」と、進み具合のバーを表示する。まだ使っていなければ「ログインしなくても、AIの読み取りを1日5回まで使えます。」と書く
- 1日の回数を使い切った時は「明日の0時に戻ります」と伝え、もう一度読み取るボタンは出さない（すぐに試しても通らないため）
- ログインしていない時の記録としてサーバーに残るのは、AIの利用回数だけ。家計データはサーバーに置かない。登録なしの利用をやめる操作は置かない（消して作り直せると、1日の回数をすり抜けられるため）
- お問い合わせの送信・深掘り・音声の文字起こしは回数に数えない。短い時間に続けた時と、同じ接続から1日に多く送った時だけ断る
- ログアウトしても端末内の家計データは消さない。そのことを画面で伝える
- ログイン中は利用枠と今月の利用回数を表示する
- アカウント削除はPasskey・ログイン状態・AI利用情報が削除されることを確認し、削除後もこの端末の家計データは閲覧・バックアップできると説明する。端末内データの全削除は別の操作にする

### 端末内の画面ロック

- 設定で明示的に有効にした場合だけ、起動時に6桁PINを求める。PINは端末内でPBKDF2によりハッシュ化し、Cloud accountや通信を使わない
- 復帰時は、アプリをバックグラウンドにしてから1分以上経過した場合に再ロックする。「今すぐロック」も設定から行える。新しいタブはそれぞれ解除が必要で、手動ロックと設定変更は他タブにも伝える
- 有効化とPIN変更時にはランダムな復旧コードを一度だけ表示する。PINを忘れた場合は復旧コードでロックを無効にして入る。設定・復旧のいずれでも家計データは削除しない
- PINを5回続けて間違えると、30秒間入力を待つ。再読み込み後も待ち時間を維持する
- ロック解除後も同じ画面と入力中の下書きを保持する。ロック画面は家計画面を隠し、ロック中のクリック・入力・画面操作を止める
- 画面ロックが有効な場合、設定で現在のPINを入力して「生体認証も使う」を選ぶと、Face IDや指紋認証など端末の本人確認でも解除できる。端末やブラウザーが対応しない場合は、使えないことを表示する
- 生体認証を登録した端末では、ロック画面の主要ボタンを「生体認証で解除」にし、PIN入力は常に残す。生体認証の取り消しや失敗ではロックを維持し、PINのやり直し回数には数えない
- PINを変更しても生体認証の登録は残る。「生体認証をやめる」にも現在のPINを求める。復旧コードで解除すると、生体認証を含むロック設定がすべて無効になる
- 画面ロックは通常UIへのアクセスを防ぐもので、保存データの暗号化やOSの画面ロックの代わりではない。Face ID / Touch IDなど個別の方式での動作は端末とブラウザーに依存する

## エラーの伝え方

「エラーが発生しました」だけにしません。何が起きたかと、次にできることを書きます。

- 写真から金額を読み取れませんでした → 金額の入力欄へ移動する
- 明細の形式を確認できませんでした → 対応しているサービスとファイルの例を表示する
- 家計簿に保存できませんでした → 入力を失わず、再試行できるようにする
- 写真を読み取れませんでした → 画像を保持し、後で読み取り直せるようにする
- カテゴリを提案できませんでした → 未分類のまま利用者が選べるようにする
- AIアカウントからログアウトしました → 端末内の家計データはそのまま使えることを伝える
- 今月の読み取り回数の上限に達しました → 画像を端末に残し、手入力へ進めるようにする

## アクセシビリティ

- 本文は16 px以上を基準にする。補足は13〜14 pxとし、それより小さい文字はナビのラベル（12 px）に限る
- 文字と背景のコントラストは4.5:1以上にする。24 px以上の大きな文字は3:1以上でよい
- タップできる場所は44 CSS px以上にする
- フォーカスの表示を消さない
- フォームには必ずラベルを付ける。placeholderをラベルの代わりにしない
- アイコンだけのボタンには読み上げ名を付ける
- 成功・警告・エラーを、アイコンと文言でも区別する
- 端末の「視差効果を減らす」設定では、アニメーションを止める

### お問い合わせ

設定のアプリ欄から独立したお問い合わせ画面を開きます。種別（不具合・改善の要望・質問）、文章入力、音声録音を置きます。録音終了後は自動で文字起こしして文章欄へ追加し、結果を利用者が確認・編集できます。文字起こし失敗時や結果の追加で4,000文字を超える時は録音を保持し、文章の編集後に再試行できるようにします。

送信した問い合わせはKakeiMatch内の管理者Inboxに保存します。送信前に、音声の文字起こしにはGoogleを利用すること、問い合わせは運用担当者が確認すること、GitHubには自動公開されないことを伝えます。必要な場合は、管理者が内容を確認してから明示的にAI分析またはIssue作成を実行します。Issueには原文をそのまま送らず、開発向けに確認した内容を使います。

「直前のアプリ動作情報を添付する」は初期状態を未選択にします。添付するのは画面名・操作種別・安全なエラーコード・オンライン状態だけであり、入力内容、金額、店名、レシート/明細内容は含まないことを示します。通常の画面にモデル名やエンコード形式を出しません。画面を移動するとマイクを停止します。失敗・オフライン・画面移動では入力を保持し、送信結果が不明の場合は重複防止のため再送を止めたことを伝えます。詳細は[お問い合わせ](CONTACT.md)に記載します。
